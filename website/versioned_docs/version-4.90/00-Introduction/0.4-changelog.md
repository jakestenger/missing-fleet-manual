# What changed, by release

![Reference](../_assets/icons/reference-light.svg) Each edition follows a Fleet minor release line, such as 4.90 or 4.91. Point releases stay within that edition: affected chapters carry inline notes, collected here with links to the relevant passages. Releases appear newest first.

When you are planning an upgrade, use this changelog to find the changes that affect your devices and workflows. Each entry points to the explanation in context, so you can review the relevant setup, behavior, or operating procedure before introducing the new release.

This edition covers **Fleet 4.90**, checked against 4.90.0. The entries below link to the passages affected by point releases in that line.

## Fleet 4.90.2

Fleet 4.90.2 was a bug-fix point release on the 4.90 line. One fix touches behaviour the manual teaches.

| Area | What 4.90.2 changed | Where in the manual |
|---|---|---|
| Policies · queue | Fleet-initiated activities (policy-automation installs and scripts, and iOS/iPadOS scheduled app updates) are released to hosts at a configurable rate rather than all at once, and user-initiated activities take precedence over queued Fleet-initiated work on the same host. | [5.9 Queueing and duplicates](../05-manage-devices/5.9-automate-remediation-with-policies.md#queueing-and-duplicates) |

## Fleet 4.90.1

Fleet 4.90.1 contained fixes and no new features. This table lists the fixes that affect behaviour covered in the manual, with links to the notes in context.

| Area | What 4.90.1 changed | Where in the manual |
|---|---|---|
| Apple MDM · labels | Re-enrolling an Apple host through ADE could clear its built-in label memberships and not restore them, so label-scoped profiles, software, and OS updates stopped reaching a host that had done nothing wrong. 4.90.1 restores the memberships during the re-enrollment reset and backfills hosts already affected. | [3.2 The ADE sequence, in order](../03-connect-devices/3.2-enroll-macos-devices.md#the-ade-sequence-in-order) · [8.3 Error strings worth recognising](../08-troubleshooting/8.3-server-logs.md#836-error-strings-worth-recognising) |
| Apple MDM · labels | A host re-enrolling through DEP could receive a profile scoped by a dynamic *exclusion* label before it had reported any label results, slipping past the guard that withholds label-scoped items until a host has reported. 4.90.1 closes that gap. | [1.3 Why exclude targeting behaves differently from include](../01-foundations/1.3-hosts-fleets-labels.md#why-exclude-targeting-behaves-differently-from-include) |
| Apple MDM · profiles | Above a certain host count, a profile-delivery page was judged full after duplicate commands were removed rather than before, so a subset of Macs never received a profile. 4.90.1 tracks fullness before the dedupe. | [8.8 Profile status values](../08-troubleshooting/8.8-apple-mdm-diagnostics.md#887-profile-status-values) |
| Software | The hourly auto-update job could keep an app's previous install script, which names the old installer file, so the install failed; and a new build that reused the same shortened version did not swap in the new file. 4.90.1 fixes both. | [5.4 Automatic updates to the software library](../05-manage-devices/5.4-manage-software-and-applications.md#automatic-updates-to-the-software-library) |
| Policies | A policy automation could act on an App Store app added for a platform other than the host's, instead of skipping it. 4.90.1 skips it. | [5.9 Validate policy, action, scope, and transport compatibility](../05-manage-devices/5.9-automate-remediation-with-policies.md#validate-policy-action-scope-and-transport-compatibility) |
| Policies · software | When a host's upcoming-activity queue was not draining, App Store install suppression did not hold, so automatic updates and policy automations could queue a duplicate install. 4.90.1 skips an app that already has an install waiting. | [5.9 Queueing and duplicates](../05-manage-devices/5.9-automate-remediation-with-policies.md#queueing-and-duplicates) |
| Windows MDM | A removed Windows profile stayed listed under Host details → OS settings when another profile on the same host still enforced every setting it had covered, so nothing was ever sent to clear the row. 4.90.1 clears it. | [8.9 Version notes](../08-troubleshooting/8.9-windows-mdm-diagnostics.md#version-notes) |
| Operations | One 4.90.0 migration could run for hours on deployments with many host certificates. 4.90.1 fixes that specific migration, though not the general fact that migration time cannot be predicted. | [7.3 There is no duration model](../07-operate-fleet/7.3-upgrade-fleet-and-fleetd.md#there-is-no-duration-model) |
