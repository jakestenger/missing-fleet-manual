# Enroll Android devices

![Explanation](../_assets/icons/explanation-light.svg) Fleet can create a managed work space on a personal Android device or enroll a company-owned device for full management. The ownership choice determines the setup experience and available actions. Both paths use a per-device enrollment token and an Android Enterprise connected to Fleet.

Prepare the Android Enterprise connection in [2.12](../02-administer-and-deploy-fleet/2.12-bind-android-enterprise.md) before enrolling devices. Keep the Fleet server URL stable: the default proxy path supports one enterprise per URL and Google’s event subscription remains tied to that address.

## Android: choosing a path

![Reference](../_assets/icons/reference-light.svg) Choose ownership before distributing enrollment instructions so the employee sees the appropriate setup flow and administrators receive the intended management capabilities.

| Path | Use it when | What the console shows |
|---|---|---|
| **Work profile** | The device belongs to the person carrying it. Fleet manages a work profile beside their personal one | On (manual - personal) |
| **QR code at initial setup** | The device is company-owned and factory-fresh, or has been reset | On (company-owned) |

The company-owned QR flow starts at Android’s initial setup screen. Use a new or factory-reset device and follow the prompt to tap the first screen. A device that has completed setup needs a factory reset before it can use this path, so include management enrollment in the unboxing plan.

Company-owned devices support wipe. For a personally owned device, use unenrollment to remove its work profile; Fleet refuses a device wipe on that ownership type. Lock is supported on both, subject to the Premium requirement below.

| Path | Lock | Wipe |
|---|---|---|
| Work profile (personal) | Yes, **Fleet Premium** | **No.** Unenroll instead, which removes the work profile |
| QR code (company-owned) | Yes, **Fleet Premium** | Yes, **and this one is free** |

Both need Android management configured, and **both** need Fleet to consider the host connected, on Free and Premium alike.

Company-owned Android wipe is available on Free. Lock requires Premium on every supported platform, and other supported wipe operations require Premium as well. ChromeOS supports neither operation. These license rules apply alongside the connection and ownership requirements above.

Work profile enrollment does not become company-owned later either, for the same reason. Decide before the device reaches a person.

Fleet’s triage notes also mention Google account-based enrollment without documenting how to start it or the resulting MDM status. The procedures here cover the two established paths. If you use the additional route, record its observed behavior with the escalation evidence described in [8.13](../08-troubleshooting/8.13-escalation.md).

<a id="what-both-paths-actually-do"></a>

### How both Android enrollment paths work

You do not build a package or deliver a profile. You ask Fleet for an **enrollment token** and give it to the device: as a link on the work-profile path, as a QR code on the other.

| Fact | Value |
|---|---|
| Where the token comes from | Fleet, which asks Google's API through its proxy |
| What Fleet puts inside it | Your enroll secret, and an identity-provider UUID where one applies |
| Reuse | **One device per token.** Fleet marks it single-use |
| Lifetime | One hour, which is Google's default and Fleet does not override it |

That payload is how a device Fleet has never seen ends up in the right fleet, and, **when an identity-provider UUID is included**, attached to a person. The UUID is optional: Fleet accepts an empty one where authentication is not required, and creates the person-to-device association only when it is present. An enrollment URL emailed round without it produces managed devices with no owner recorded.

Fleet validates the enroll secret when creating the token. Correct an invalid secret at that step before distributing instructions to a device.

Generate the per-device token near the enrollment session. Its one-hour lifetime makes a saved or printed QR code unsuitable as a lasting runbook artifact.

[8.10](../08-troubleshooting/8.10-android-diagnostics.md#8108-enrollment-paths) has the token endpoint, the exact settings, and the enrollment failures worth recognising.

![How-to](../_assets/icons/howto-light.svg) Open **Add hosts**, choose **Android**, and pick **Personal (BYOD)** or **Company-owned (fully-managed)**. Fleet generates a different enrollment URL for each: the company-owned one carries `fully_managed=true`, which is what turns off personal usage on the resulting token. Copy the URL and send it to the person, or take the QR code for the company-owned path.

If the tab tells you to turn Android MDM on instead of showing a URL, the enterprise is not bound yet and [2.12](../02-administer-and-deploy-fleet/2.12-bind-android-enterprise.md) is where that happens.

<a id="what-you-get-and-what-you-do-not"></a>

### Management capabilities and limits

Android uses Google’s Android Management API, normally through Fleet’s proxy, with a direct-to-Google option also supported. Google pushes enrollment events and status reports; Fleet polls hourly to reconcile device existence.

Fleet also installs a small companion app through the host’s policy. The app enrolls with Fleet, installs certificates, and reports certificate results directly. It is present on Free and Premium, but creating the certificate templates it consumes requires Premium. This app supplies certificate installation that Google’s management API cannot perform directly ([2.12](../02-administer-and-deploy-fleet/2.12-bind-android-enterprise.md)).

Android has no osquery, live or scheduled reports, or scripts. Use Fleet’s returned management state and Android Device Policy’s device-side screens to investigate problems; [8.10](../08-troubleshooting/8.10-android-diagnostics.md) follows those evidence sources.

For work-profile devices, Fleet reports an enterprise-specific identifier as the serial number and UUID. It is unique to that work profile in your organization and stable across factory resets. Account for it when matching inventory to a hardware register ([2.12](../02-administer-and-deploy-fleet/2.12-bind-android-enterprise.md)).

![How-to](../_assets/icons/howto-light.svg) Start verification with the host record and MDM status in Fleet. If the record is absent or incomplete, Android Device Policy and the Fleet companion app provide device-side context alongside the Google event path.

Fleet can create the host from an `ENROLLMENT` notification, but receiving one is not sufficient. If the device says it enrolled and Fleet has no host, **the notification not arriving is one explanation and not the only one**: Fleet also validates the payload, re-checks the enroll secret embedded in the token, and does database work after receipt, any of which can fail on a notification that arrived perfectly. A status report for an unknown device can also enrol it, so the enrollment event is not the only path in. Start at the return path ([8.10](../08-troubleshooting/8.10-android-diagnostics.md)) and rule out a received-but-rejected payload before concluding Google never called.

Re-enrollment restores the Android device’s last known fleet, even if its host row was deleted. The token’s enroll secret places devices Fleet has never seen. If a returning device needs a different fleet, transfer it explicitly.

## Who owns it afterwards

![Reference](../_assets/icons/reference-light.svg) **The Android Enterprise binding**, and the Google account that created it. Deleting the enterprise makes Fleet delete it at Google, drop its own record, turn Android MDM off and mark every Android host unenrolled; Fleet's guidance is that the work profiles go from the devices too, which is Google's behaviour rather than something the checkout establishes. Either way it is a poor thing to reach for while troubleshooting ([8.10](../08-troubleshooting/8.10-android-diagnostics.md)).

**The Fleet server URL**, which Android fixes. If a hostname change is anywhere in your plans, make it first.
