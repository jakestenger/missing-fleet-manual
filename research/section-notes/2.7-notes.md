## The finding that carries the chapter

**Changing `server_url` costs an end-user action on every Apple device.** Verbatim from
`yaml-files.md`:

> `server_url` is the base URL of the Fleet instance. If this URL changes and Apple (macOS,
> iOS, iPadOS) hosts already have MDM turned on, **the end users will have to turn MDM off
> and back on** to use MDM features. (default: provided during Fleet setup)

This validates the stub's "identity boundary" framing with a concrete, verified consequence
rather than an assertion. It is the single most expensive-to-reverse setting in Fleet.

Related:
- `sso_server_url`: optional, for when the URL administrators use to sign in differs from the
  base URL. "SSO will only work from this URL."
- `server_url_prefix` / `FLEET_SERVER_URL_PREFIX`: form `/apps/fleet`, no trailing slash.
  Changing it also affects URLs given to osquery via flagfile, the configuration Fleet
  serves, the prefix `fleetctl` uses, and the IdP redirect URL.

## org_info
`org_name`, `contact_url`, and four logo keys: `org_logo_path_light_mode`,
`org_logo_path_dark_mode`, `org_logo_url_light_mode`, `org_logo_url_dark_mode`. **Only one of
each path/url pair may be set.** Recommended sizes: 256x256 square, 516x256 wordmark; PNG,
JPEG, WebP or SVG.

`contact_url` **appears in error messages presented to end users**, default
`https://fleetdm.com/company/contact`. Leaving the default sends your users to Fleet.

Can only be configured for "All fleets" (`org_settings`).

## The GitOps precedence exception
`host_expiry_settings`: "**If this setting is not defined in your YAML files, unlike all
other settings, it will not get reset to the default values.**"

Every other setting is reset to default when absent from GitOps YAML. This one is not. A
genuine exception to the declarative model, and exactly the kind of thing `a.3` exists for.

- `host_expiry_enabled` (default `false`), `host_expiry_window` days, must be > 0 when
  enabled. Configurable at org level and per fleet.

## activity_expiry_settings
- `activity_expiry_enabled`: cleans up activities **and associated live query data** older
  than the window.
- `activity_expiry_window`: days retained.
- **Activities linked to a host are preserved until the host is deleted.**
- `preserve_host_activity_on_reenrollment` (default `false`): keeps host activity across a
  wipe and re-enrollment. **Only supported for company-owned (ADE) Apple hosts.** Max
  activity age still applies.

## 2026-08-25 review pass: GitOps mode is not an authorization boundary

Independent review on `gpt-5.6-sol`. One correction with security consequences, two additions.

### Corrected: GitOps mode overstated as change enforcement

As published: "This does not prevent change, it relocates it ... What it removes is the quiet
divergence."

That reads as a technical write boundary. It is not.

| Fact | Source |
|---|---|
| "GitOps mode is a UI-only setting. API permissions are restricted based on user role." | `frontend/pages/admin/IntegrationsPage/cards/ChangeManagement/ChangeManagement.tsx:208`, verbatim tooltip |
| Requires Fleet Premium | `docs/Configuration/yaml-files.md:789` |
| Configurable only at `org_settings`, not per fleet | same, `:792` |
| Labels are explicitly exempt: enabling GitOps mode "does not restrict creating/editing labels via the UI" | same, `:28` |

The labels exemption has a reason worth keeping: omitting the `labels` key from YAML deletes
labels not listed, so making labels read-only in the interface would leave no safe place to
manage them. The chapter now carries the exemption and the reason.

An administrator who read the published wording could conclude that enabling GitOps mode
prevents out-of-band writes. It does not touch API authorization at all.

### Added: the Android consequence of a server URL change

The section covered the Apple consequence and stopped. On Android the URL cannot change at all,
because the Pub/Sub subscription is bound to one address. Established for 2.11 at
`docs/Contributing/product-groups/mdm/android-mdm.md`, Known issues. A reader deciding a
hostname needs both consequences in the place where the decision is made, not one here and one
three chapters later.

### Added: the `server_url_prefix` naming collision

`server_url_prefix` is organization configuration; `server.url_prefix` is process configuration.
Different planes, near-identical names. Flagged inline rather than left to the reader.
