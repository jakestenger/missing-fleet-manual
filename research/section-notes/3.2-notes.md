## Derived

- **The two-channel framing** that opens the chapter is the book's own, built on 1.2's five channels. It is a teaching device, not a Fleet concept, and it is the reason this chapter is organised the way it is.
- **"Changing your mind means re-enrolling"** follows from the access rights being baked into the profile the device holds. Fleet exposes no way to change a delivered profile's access rights, and nothing was found that does; stated as a consequence rather than as a documented behaviour.
- **The ordering requirement for `--use-system-configuration`** (MDM, then profile, then package) follows from the package having no URL or secret of its own. Fleet does not document the ordering in those words.

## First independent review, 2026-08-27: NOT READY. Rewritten.

The chapter was organised around a claim that is false at the tag, so this was a rewrite rather than a correction pass. Seven factual defects, all confirmed in the source before applying.

**Fleet installs fleetd on manual macOS enrollments too, and the chapter said the opposite.** `AppleMDMPostManualEnrollmentTask` is queued for every non-DEP Apple enrollment, and `runPostManualEnrollment` calls `installFleetd` for macOS, which sends `InstallEnterpriseApplication` with Fleet's own base package. The ADE path has the **only** opt-out, `macos_setup.manual_agent_install`, and the manual path has none. So the chapter had the behaviour exactly inverted on both halves: it said ADE always installs and manual never does.

The consequences went well beyond one paragraph, which is why the chapter is restructured rather than patched:

- The decision table's whole third column was the wrong question.
- **The half-enrolled state is not an ADE problem.** A link-enrolled Mac reaches it by the same one-shot command, with console status `On (manual)` rather than `On (company-owned)`. Corrected here and in **8.1, 8.4 and 8.8**, all three of which framed it as ADE-only.
- Building a package is now given its three real reasons: Macs you are not MDM-enrolling, ADE with the agent install turned off, and getting the agent on before MDM or into a different fleet.

**The manual path's artifact is a link, not a downloaded profile.** With Apple MDM configured, the Add hosts modal shows an `/enroll` URL with the company-owned or personal choice, not a package command. That is Apple's over-the-air enrollment, implemented in the **free** service with no licence branch. **This resolves the licensing question the first draft left open as unverified**, and resolves it in the useful direction: Fleet Free can enrol Macs. The Premium gate is on a *different* artifact, the unsigned manual enrollment profile endpoint, and the first draft had conflated them into "not documented as a supported matrix anywhere".

**`--use-system-configuration` imposes no installation order.** Orbit loops, retrying every thirty seconds, and its own comments describe the package running during ABM bootstrap before the profile exists. The first draft called the ordering "the whole trick" and told the reader an out-of-order install has nothing to enroll against. It waits. The corrected advice is to deliver the profile rather than reinstall the agent.

**Both `secret.txt` claims were wrong for the steady state**, in opposite directions, and both errors were mirrored in Part VIII:

| Claim | Actually |
|---|---|
| A packaged secret sits in `secret.txt`, where an old one hides after rotation | Orbit moves it into the Keychain on first launch and **deletes the file**. The installer artifact is the rotation concern; a running Mac's file is not |
| A `--use-system-configuration` host has no `secret.txt`, and absence is the marker | It **writes** `secret.txt` and `fleet_url.txt` once the profile arrives. Absence dates the host to before the profile rather than identifying the package |

8.2's and 8.4's Orbit-root rows carried the same misreading and are corrected with it.

**`--enable-scripts` is not permanent on macOS.** An agent started without it polls Fleet's fleetd configuration profile and enables scripts from its `EnableScripts` value, which Fleet's generated profile always sets true. So on an MDM-enrolled Mac carrying that profile, scripts end up on either way. The package-time framing holds only for a Mac without it, and the chapter now says which.

**The ADE push timestamp was read backwards.** Fleet's own tooltip defines it as the last time Apple reported the host *retrieved* its assigned profile. The first draft said it meant the device "was never told to renew its enrollment", pointing the investigation at Fleet's outbound path when the fact on screen is about the device. Corrected here and in **8.8**.

### Unsupported claims removed rather than softened

"One well-known failure", "the most common", and the flat assertion that changing enrollment type means re-enrolling. The last is now stated as what the source supports — Fleet exposes no way to change a delivered profile's rights, and nothing establishes a supported path between them — rather than as a rule. The APNs annual lifetime and Apple Account rules are marked as Apple's rather than presented as verified Fleet behaviour.

### Omissions the review found, now covered

1. **Who can read an enroll secret.** Global and fleet admin or maintainer only; technicians, observers, Observer Plus and GitOps cannot. It decides whether a help desk can enrol machines at all.
2. **End-user authentication on the link.** With it on, `/enroll` goes to the identity provider first and attaches the returned identity to the host.
3. **Network exposure.** A link-enrolled Mac needs `/enroll` and the over-the-air profile endpoint reachable, not only the MDM protocol endpoints.

### Not done

The reference section no longer promises `fleetctl package` flags in **a.7**, which is an empty outline. Sol was right that the handoff was false; the honest fix was to stop making it rather than to write the appendix in this pass. 3.3 and 3.4 make no such promise.

## Confirming review, 2026-08-27: NOT READY, applied

Most of the rewrite confirmed: the Free-tier resolution, the `/enroll` link workflow, `--use-system-configuration` waiting rather than requiring an order, `--enable-scripts` on an MDM-enrolled Mac, the ADE push-time reading, fleet placement, who can read an enroll secret, and the identity-provider redirect. Part VIII's inherited errors confirmed fixed in 8.1, 8.4 and 8.8.

What remained is one habit in six places, and it is the one this session kept producing: **the rewrite corrected a wrong universal by asserting the opposite universal.**

**"Fleet installs fleetd on every macOS MDM enrollment" overshot twice in one sentence.** ADE has an opt-out, which the same chapter documents forty lines later, so "every" is false. And what the source establishes is that Fleet **sends the command**; whether the agent arrives is the half-enrolled state the chapter's own last section is about. Both corrected, and the phrasing is now "sends the agent-install command" throughout, which is what can be verified and what the failure mode is about.

**The configuration key was wrong.** `macos_setup.manual_agent_install` is the Go field's JSON name; the administrator-facing YAML key is `setup_experience.macos_manual_agent_install`, and printing an internal name where a reader will copy it is worse than not naming it. Corrected, **and it turned up a prerequisite the chapter did not have**: Fleet refuses to enable the option without a bootstrap package, with a message saying so. That is consistent rather than arbitrary, since something has to carry the agent instead.

**Two frequency claims, one of them newly introduced.** "The most common 'it did not work' on this path" and "an ADE support question is usually about which of these did not happen". The second was written during the rewrite, which is worth noting because `check-frequency-claims.py` did not catch either: they rank a *symptom* rather than a *cause*, so they sit outside the pattern the checker looks for. Recorded as a known limit of that check rather than widening it into noise.

**The `secret.txt` correction contradicted itself.** The `--use-system-configuration` paragraph correctly says the file is written once the profile lands; the verification section then said Orbit moves it into the Keychain and deletes it, as a universal. Both are true of different cases, so the chapter now says **`secret.txt` tells you nothing either way on macOS** and gives both.

**"Three cases, and none of them is a manually enrolled Mac"** was contradicted by the section below it, which prescribes building a package to recover a half-enrolled Mac. Four cases now, with the fourth named as the one you meet after something went wrong.

**The a.8 handoff was mis-scoped.** A Mac enrolling by link needs `/enroll` and the over-the-air profile endpoint, which a.8 lists under iOS and iPadOS only. The chapter now says so and calls it a gap in a.8 rather than implying the reference covers it.

**One phrase left as-is and worth recording.** "Treat the choice as one you cannot expect to undo in place" replaced "you will have to re-enroll", because the source establishes the rights masks and Apple's narrowing constraint and does not establish the absence of every possible transition. The weaker phrasing is what the source supports, and the operational advice is unchanged.

## Fourth round, 2026-08-27

NOT READY, and the finding is a **reviewer retraction of its own wording that I had adopted**, which is now the fifth today.

I had written that on a `--use-system-configuration` host the absence of `secret.txt` identifies the window before the profile arrives. It does not. Orbit reads the file through the generic loader first, which may move the value into the Keychain and delete it; then the system-configuration loop writes it again if the profile is present, and falls back to stored files or the Keychain if it is not. **So absence is consistent with a healthy host of either kind**, and `secret.txt` is not a classifier for the package type, the profile's arrival, or the host's health. The chapter now says so and sends the reader to the node key and the process state.

That false classifier was still living in 8.2's and 8.4's "Present means" columns too, both of which described the file as the secret the package was built with. A system-configuration host writes the same file at runtime.
