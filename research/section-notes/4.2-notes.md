# 4.2 Run queries and read reports, citation ledger

First draft, 2026-08-27, against `fleet-v4.90.1` (dd0200f062).

## Stated

| Claim | Source at the tag |
|---|---|
| Fleet keeps the newest result per host per query, overwriting that host's previous rows | `server/service/osquery.go`, the result-submission path calling `overwriteResultRows` |
| `query_reports_disabled` stops storage **and deletes rows already stored** | `server/service/osquery.go` skips `saveResultLogsToQueryReports` when set; `cmd/fleet/cron.go` runs the cleanup that removes stored rows |
| `discard_data` and a non-snapshot logging type each stop storage for that query | `server/service/osquery.go`, the `DiscardData || Logging != LoggingSnapshot` skip |
| The report row cap defaults to 1000 per query | `server/fleet/app.go`, `DefaultMaxQueryReportRows = 1000`, returned by `GetQueryReportCap` |
| A host whose single result set exceeds the cap stores nothing, and a cleanup job trims across hosts keeping the most recent rows | `server/datastore/mysql/query_results.go`; `cmd/fleet/cron.go` |
| Fleet marks a report clipped | `server/fleet/queries.go`, `ReportClipped` |
| Forwarding happens only when a query's automations are enabled, which default off | `server/service/osquery.go` filters on `dbQuery.AutomationsEnabled`; `automations_enabled` defaults to `0` in `server/datastore/mysql/schema.sql` |
| Queries carry a platform selector, a minimum osquery version, an `observer_can_run` flag and a logging type | `server/fleet/queries.go`, the `Query` and payload structs |
| Valid logging types are snapshot, differential and differential-ignore-removals | `server/fleet/queries.go`, `LoggingSnapshot` and siblings |
| A query's platform selector takes the generic values, not the stored host platform | `server/fleet/queries.go` validates against `darwin`, `windows`, `linux`, `chrome`; established for 4.1 that a Fedora host stores `rhel` |
| Fleet has a server setting that disables live reporting | `server/fleet/app.go`, `LiveQueryDisabled` |
| ChromeOS has no scheduled reports because the extension never posts to the logging endpoint | `ee/fleetd-chrome/src/background.ts` uses enroll and distributed read/write only; `articles/chrome-os.md` |
| `fleetctl` does not retrieve stored report rows | Established during 1.1's fourth round: `fleetctl query` runs a fresh live report, `fleetctl get queries` lists definitions |
| Fleet records per-query execution statistics from hosts | `scheduled_query_stats` in `server/datastore/mysql/schema.sql`, surfaced on the query |

## Derived

**"Execution, storage and forwarding are three decisions."** Each mechanism is source-checked; presenting them as three independent axes is the chapter's framing, and it is what makes the rest of the chapter usable.

**"A clipped report has unknown coverage and unknown freshness."** Follows from the two cap behaviours: an oversized host stores nothing and the cleanup trims across hosts. This wording was adopted from 1.1's third review, where the reviewer proposed it after retracting a simpler "freeze" description; it is repeated here because it is the safe operational conclusion rather than because the reviewer said it.

**The results-table reading rows.** Individually source-backed; the arrangement into what each appearance is consistent with is editorial.

## Deliberately not stated

**No live-report row or host limit is given.** The tag has a rest period and campaign machinery, but establishing a reader-facing limit needs a check I have not done, and inventing one would be worse than omitting it.

**No claim about how often a clipped report occurs.** The cap is per query across the estate, and the chapter gives the arithmetic (fifty rows per host reaches 1000 at twenty hosts) rather than a frequency.

## Boundaries held

Query cost, the osquery watchdog and denylisting are named and handed to 4.6 rather than explained. Log destination configuration is 2.5's. Diagnosing a query that returns nothing from hosts that should answer is 8.7's. The platform-value vocabulary was established in 4.1 and is cited rather than restated.
