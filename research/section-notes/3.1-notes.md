## 2026-08-25 review pass

Independent review on `gpt-5.6-sol`, run after the chapter was written and committed.

### Corrected: the chapter generalized one enrollment path into all of them

As published, the scope line promised "the decisions common to enrolling anything" and then
described the fleetd path. Two rules did not carry:

| Rule as written | Where it fails | Source |
|---|---|---|
| The enroll secret determines fleet assignment | Automatic Apple enrollment places by the default fleet configured per platform against the Apple Business token | `articles/configuring-default-teams-for-devices-in-fleet.md:1-24`, and 2.7 of this manual |
| Retirement is stop the agent, then delete | iOS and iPadOS have no agent to stop, and a device still assigned in Apple Business returns at the next sync | same, and 2.7 |

**2.7 of this manual documents the Apple placement path correctly.** The contradiction was
between two chapters of this book, not between the book and Fleet. The §27 consistency read is
scoped to a single chapter and could not see it.

**That is a gap in the rule as written**, and worth recording: a chapter claiming to generalize
needs checking against what the book already says elsewhere, not only against itself.

The chapter now opens with the three paths and says plainly that what follows is the fleetd one.
Retirement is now framed as "deletion alone never retires a host, and what you must stop first
depends on the path", which holds for both.

### Corrected: the identity model collapsed several credentials into one

As written: "by default is an enrollment-derived node key and can optionally be a hardware-backed
certificate."

Two errors in one sentence. Fleet issues **two** node keys, an orbit node key stored in a
root-only file and an osquery node key stored in osquery's own database, each authenticating its
own component's requests (`articles/fleetd-authentication.md:29,52-60`). And the TPM certificate
is an additional signature layered onto authenticated requests rather than an alternative to a
node key.

### Corrected: rotation had no stop condition, and revocation is not limited to new hosts

As written: "remove the old one once nothing uses it."

`docs/Configuration/agent-configuration.md:66`, verbatim: "If you revoke an old enroll secret, the
`command_line_flags` won't update for hosts that enrolled to Fleet using this old enroll secret
... For these hosts, all existing features will work as expected."

So revocation silently degrades already-enrolled hosts, which keep working in every other
respect. The chapter now gives a real rotation sequence and states that Fleet does not report
which secret a host enrolled with, so the final check is behavioural rather than a query.

### Also corrected

Multiple enroll secrets are available on Fleet Free as well as Premium; Premium adds per-fleet
secrets alongside global ones (`articles/fleetd-authentication.md:22-24`). The chapter had not
said which tier supported what.
