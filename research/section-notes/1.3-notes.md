## 2026-08-25 review pass

Independent review on `gpt-5.6-sol`.

### Corrected: duplicate identifiers do not always merge

As published: "**Two devices sharing a hardware identifier merge rather than fail** ... Fleet
records this rather than rejecting it, so the symptom is one host record whose details keep
changing, rather than an error anyone notices."

True on the default path and false on another. `server/datastore/mysql/hosts.go:2675-2690` logs a
warning and lets the newer enrollment overwrite, but immediately below, an enrollment carrying a
TPM-backed host identity certificate whose host ID does not match is **rejected** with an error.
The comment is explicit: "We do not support duplicate host identifiers when using TPM-backed host
identity certificates."

So the same underlying problem presents as a silent merge in one deployment and a loud enrollment
failure in another, and the published text told a reader on the second path to look for a symptom
they will never see. Both behaviours are now described, along with what decides which one applies.

Another instance of the recurring pattern: a correct reading of one code path stated as a
universal rule. `build/check-absolutes.py` did not flag "merge rather than fail"; the phrasing is
outside its pattern set.

### Corrected: transfer described as close to a no-op

As published: "a transfer between two similarly configured fleets is close to a no-op on the
device itself."

Profile reconciliation for Apple and Windows is deferred to a periodic job rather than performed
during the transfer (`server/fleet/datastore.go:1657-1666`), so the host settles over the
following minutes. Little is asked of the device, but it is not immediate, and an administrator
verifying a transfer straight afterwards will see an incomplete state that is not a fault.

### Checked and found already correct

The review suggested the transfer section understated the disk encryption consequence. It does
not: the chapter already states that moving a host to a fleet that does not enforce disk
encryption removes the escrowed recovery key, that it applies across platforms rather than only
macOS, and that the destination should be confirmed first. Verified against
`server/datastore/mysql/disk_encryption.go:358-386`, where the absence of a FileVault profile on
the destination triggers `bulkDeleteHostDiskEncryptionKeysDB`, and the comment confirms the Apple
profile governs Windows and Linux hosts too. **No change made.**

Recorded because reviewer findings are not automatically right, and this one bundled a correct
observation about the deletion section with an incorrect one about the transfer section.

### Recorded, not fixed

- The chapter opens by saying a fleet duplicates policies, reports and labels, and a later table
  says global policies, reports and labels also apply inside fleets. Both are describing real
  behaviour, and together they do not give a reader a safe design rule. Needs the scope model
  stated once, properly, rather than twice from different angles.
- Targeting is presented as one universal three-mode control. The modes and valid combinations
  vary by item: policies expose `labels_exclude_all`, profiles allow an exclusion combined with
  one inclusion mode, and software differs again. The Premium prerequisite on these fields is
  also absent. This is a.3's material and needs the appendix to exist.
