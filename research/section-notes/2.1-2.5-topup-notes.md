## Verified and added

### 2.3 — Fleet refuses to remove the last global admin
`server/service/users.go`. Demotion fails with the error string `cannot demote the last
global admin`, raised for both the `global_role` and `teams` paths. Deletion goes through
`DeleteUserIfNotLastAdmin` and returns `ErrLastGlobalAdmin`.

Two details worth having: the check is **atomic**, with a source comment naming the TOCTOU
race it prevents, so two administrators demoting each other simultaneously cannot both
succeed. And the guard counts role holders rather than humans, so an API-only identity
holding global admin satisfies it. That is the basis for the warning about keeping a human in
the role.

### 2.4 — GitOps mode makes the interface read-only
`docs/Configuration/yaml-files.md`. `gitops_mode_enabled` shows GitOps-managed sections of
the UI as read-only with a tooltip pointing at the repository. `repository_url` is required
when it is on and must be a valid `http://` or `https://` URL. Configurable at "All fleets"
only.

**This is a second instance of the preservation exception**, and it matters: "If `gitops:` is
not provided in your YAML file, any existing GitOps mode settings will be preserved." The
chapter already documented the same behaviour for `host_expiry_settings`. Two instances make
it a pattern rather than a quirk, and the chapter now says so.

### 2.5 — oversized events are dropped, not truncated or retried
`articles/log-destinations.md`. Events are batched before sending and an event over the
destination's limit is discarded with a notice to the Fleet server log. The limits differ by
destination: 1MB for one, 10MB for another. The chapter states the behaviour and that limits
vary, without pinning per-destination figures that belong in `a.3`.

### 2.1 — the four decisions that are expensive to reverse
Assembled from claims already verified elsewhere in this manual rather than newly researched:

(2.1's own ledger), the single-writer constraint (1.6), and the identity-provider argument
(2.2). No new product claims were introduced.

## Deliberately not added

- **Per-destination size limits as a table.** Reference material, and `a.3` is its home
  under §17.
- **A restart-required list for 2.4.** Searched the configuration docs and found no
  authoritative enumeration. The existing "if changing it requires a restart, it is a server
  setting" test stands as the working rule, and inventing a list would be worse than not
  having one.
- **Retry semantics for audit delivery.** The docs state that nothing is replayed, which the
  chapter now says; the underlying mechanism was not traced, and the chapter does not claim
  to know it.
