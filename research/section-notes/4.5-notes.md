# 4.5 Monitor fleet-wide state, citation ledger

Drafted 2026-08-27, rewritten the same day after review. All against `fleet-v4.90.1`
(dd0200f062).

## Stated

All count definitions come from `GenerateHostStatusStatistics` in
`server/datastore/mysql/hosts.go`, read directly rather than from the API documentation.

| Claim | Source at the tag |
|---|---|
| Online is last seen within `LEAST(distributed_interval, config_tls_refresh)` plus 60 seconds | The `online` expression; `OnlineIntervalBuffer = 60` in `server/fleet/hosts.go` |
| Online and offline use `COALESCE(hst.seen_time, h.created_at)` | Both expressions in the same query |
| Missing uses a wider expression including MDM check-in | `hostEffectiveLastSeenExpr`: `COALESCE(GREATEST(seen_time, nes.last_seen_at), ...), detail_updated_at, created_at)` |
| Missing and MIA are byte-identical expressions | The `mia` and `missing_30_days_count` lines of the same SELECT |
| MIA is deprecated since 4.15 and slated for removal in 5.0 | `server/fleet/hosts.go` line 1178 note, and the comment at line 31 |
| The 30-day threshold is fixed | `MIADuration = 30 * 24 * time.Hour`, and the literal `INTERVAL 30 DAY` in the SQL |
| Missing excludes hosts whose MDM enrollment status is Pending | `AND (hmdm.enrollment_status IS NULL OR hmdm.enrollment_status != 'Pending')` in both expressions |
| New is `h.created_at` within one day | `DATE_ADD(h.created_at, INTERVAL 1 DAY) >= ?`, matched by the list filter at line 1705 |
| Low disk space is in gigabytes and excludes negative values | `hd.gigs_disk_space_available >= 0 AND hd.gigs_disk_space_available < ?` |
| Low disk space is dropped rather than refused without a licence | `if lowDiskSpace == nil { summary.LowDiskSpaceCount = nil }`, with the service layer gating the parameter |
| Automated enrollment errors count failed **or throttled**, over non-deleted assignments | `hdep.deleted_at IS NULL AND hdep.assign_profile_response IN (failed, throttled)` |
| The per-platform breakdown is a total per platform, not a status breakdown | The second statement in the same function, `COUNT(*) ... GROUP BY h.platform` |
| The webhook takes enable, URL, host percentage and days count | `HostStatusWebhookSettings` in `server/fleet/app.go` |
| One interval drives both the host status and failing policies webhooks | `server/fleet/app.go` comment on `Interval`: "This value currently configures both the host status and failing policies webhooks" |
| The webhook fires at or above the percentage | `if percentUnseen >= settings.HostPercentage` in `server/webhooks/host_status.go` |
| The webhook uses osquery seen time only | `TotalAndUnseenHostsSince`: `COALESCE(hst.seen_time, h.created_at)`, with no MDM term |
| The payload carries the full list of unseen host IDs | The `host_ids` key in the payload map |
| Global and per-fleet webhooks both evaluate, and one fleet's failure does not stop others | `TriggerHostStatusWebhook` calling both; the per-team loop appends to a multierror and continues |
| Labels are dynamic, manual or host vitals | Established for 1.3 |
| Uptime history records which hosts were online, as a bitmap per bucket | `UptimeDataset.Collect` in `server/chart/datasets.go`, storing `NewBitmap(hostIDs)` from `FindOnlineHostIDs` |
| A bucket with no online hosts records nothing | `if len(hostIDs) == 0 { return nil }` in the same function |
| Collection buckets are hourly | `now.UTC().Truncate(time.Hour)` with a `time.Hour` bucket size |
| Default display resolution is three hours for both datasets | `DefaultResolutionHours()` returns 3 for `UptimeDataset` and `CVEDataset` |
| Vulnerability history collects every severity, over tracked software and OS vulnerabilities | `CVEDataset.Collect` comment: "Collect CVEs at all severities on the curated set of tracked software and OS vulnerabilities. Display-time narrowing" |
| Disabling a dataset deletes its collected rows | `enqueueHistoricalDataScrub` in `server/fleet/historical_data.go`: a global flip "will DELETE every row for the dataset" |
| Host expiry is a configurable setting | `HostExpirySettings` in `server/fleet/app.go` |

## Derived

**"The counts are not a partition."** Follows from reading the expressions together: new overlaps
online and offline, missing overlaps offline. The framing is mine.

**The mobile consequence.** That an MDM-only device is permanently offline and never missing
follows necessarily from the two expressions differing in exactly the MDM term. Stated as a
consequence, not as a documented behaviour.

**The reconciliation procedure and the recurring review** are editorial method, not product
behaviour.

**The advice to read `missing_30_days_count` rather than `mia_count`** follows from the deprecation
note, but the recommendation is mine.

## Corrected from the first draft

1. **"Missing in action: no communication for thirty days"** given as its own count. It is the same
   expression as Missing, returned twice. The first draft listed both as though they measured
   different things, and my own ledger recorded the relationship as unresolved. It is resolved:
   they are identical.
2. **"New: recently enrolled."** It is record creation within 24 hours. Fleet's own source comment
   says enrolled and the SQL says created, so this one is worth remembering as a case where the
   code comment is wrong.
3. **Low disk space threshold** was given without units. It is gigabytes.
4. **Automated enrollment errors** were described as assignments that failed, and as pointing at
   Apple Business. They include throttled responses, and the count names no cause.
5. **Uptime history retention** was given as "about a month" and buckets as "a few hours wide by
   default". Collection is hourly and display defaults to three hours; the retention figure was not
   established at the tag and has been removed rather than restated.
6. **"The activity record dates those"** for upgrades, settings changes and reorganisations. There
   is no server-upgrade activity type; `server/fleet/activities.go` defines 413 activity constants
   and none of them records a version change. Claim removed.
7. **The webhook section** omitted the shared interval, the repeat behaviour, the payload contents,
   the per-fleet variant, and the osquery-only last-seen definition that makes it fire permanently
   on a mobile-heavy estate.
8. **Turning history off** was not mentioned at all, and it is destructive.

## Deliberately not stated

**No retention window for historical data.** The first draft asserted about a month. The tag did
not establish it and I could not find it. Better absent than wrong. **Flag for a later round.**

**No claim about whether the API exposes uptime host membership or only counts.** Collection stores
a bitmap of host IDs, which is membership; the default visualisation is a checkerboard, which
suggests counts. What the read path returns was not established, so the chapter describes what is
collected and does not promise what can be retrieved. **Flag for a later round.**

**No frequency claims.** "Most deployments", "usually" and the weekend example were removed rather
than defended.

## Neighbour corrected

4.4 said vulnerability history "tracks critical severity only". Collection is at every severity
including OS vulnerabilities, and critical-only is display-time narrowing. Fixed in 4.4 in the same
commit, along with the scrub-on-disable warning, so the two drafted neighbours do not stay
consistently wrong.
