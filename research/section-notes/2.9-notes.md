**The three constants the chapter draws out are derived from this table, not stated by Fleet.** Per-instance allocation is identical at all eight breakpoints; Redis stays at three nodes and moves two instance classes across a 60x range; MySQL moves from db.t4g.medium to db.r6g.8xlarge and from two nodes to three. The derivation is arithmetic over Fleet's own published figures, so confidence is high, but it is the book's framing rather than Fleet's.

## Availability and upgrades

| Claim | Source | Confidence |
|---|---|---|
| Fleet servers must reach a writer in the same datacenter; cross-region replication for failover, writes stay local | `docs/Deploy/Reference-Architectures.md` Database HA, bolded note | High |
| Read replicas help some access patterns, notably API and fleetctl traffic | same | High |
| osquery keeps running its configuration and buffers results during server downtime, bounded by `--buffered_log_max` | same, Availability | High |
| Migrations are intended to run with the server offline, via `fleet prepare db`; usually seconds to minutes even on large installations; back up first | `docs/Deploy/Upgrading-Fleet.md:46-60` | High |

The chapter's statement that leaving old instances serving traffic against a partly migrated schema is unsupported follows from "intended to be run while the server is offline". Fleet does not describe the failure modes, and neither does the chapter.

## Verification

| Claim | Source | Confidence |
|---|---|---|
| `/healthz` returns 200 when running with healthy MySQL and Redis connections, 500 otherwise; details logged, not returned | `docs/Deploy/Reference-Architectures.md` Health checks; `server/health/health.go:41-60` | High |
| Health checkers registered are exactly `mysql` and `redis`; object storage is not checked | `cmd/fleet/serve.go:805-819` | High |

| `/metrics` is not mounted unless Prometheus basic auth credentials are set or auth is explicitly disabled; Fleet logs the disabled state at startup | `cmd/fleet/serve.go:943-956`; `docs/Configuration/fleet-server-configuration.md:3357-3402` | High |

**Not a documentation bug, but a gap worth noting.** The Reference Architectures page describes Prometheus metrics without mentioning that the endpoint is disabled by default. The configuration reference documents the behaviour correctly at `basic_auth.username`. The chapter states the behaviour plainly rather than characterising it as an error.

## Deliberately left out

- **Cloud-specific reference architecture contents** (VPC layout, subnets, ACLs, the Terraform module). Belongs to 2.10.
- **Render, GCP and Azure sections.** 2.10 and 2.11.
- **Systemd unit file and binary extraction.** 2.11.
- **Tracing configuration** (OpenTelemetry endpoints, sampling, runtime sampling adjustment). Substantial material at `docs/Deploy/Reference-Architectures.md` Traces; it is an observability topic and fits 2.12 or Part VIII better than a capacity chapter.
- **`fleetctl debug archive` mechanics and per-instance targeting.** Canonical home is 8.5 per STYLE §18; the chapter keeps only the credential-scrubbing consequence, which is a deployment decision.
- **The three-store model, Redis output buffer limits, standalone vs cluster, what is coordinated across instances, and the differing consequences of losing Redis versus MySQL.** All canonical to 1.6; 2.9 builds on them and does not restate them.
- **Redis connection settings** (`redis.max_idle_conns` default 3, `redis.max_open_conns` default 0 meaning no limit). Verified at `server/config/config.go:1360-1362` but omitted: no published sizing guidance tunes them, so including them would imply a decision the reader does not have to make.
