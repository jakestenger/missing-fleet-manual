# 7.8 Retire a Fleet deployment, citation ledger

Extracted 2026-08-30 from [`7.2-notes.md`](7.2-notes.md) (then numbered 7.3, "Back up, restore, and retire service state") when the retire section became its own chapter (P6 structural moves). The rows below moved with the section they support; drafting history is in the source ledger.

## Operational practice

The retirement order is judgement: the six steps, their sequence, and the warning that releasing devices and external assignments are the steps that hurt if skipped.

## Rejected, and why

**A missing retirement section.** Added: shutting Fleet down leaves devices enrolled, credentials
live and external assignments standing, and those are the steps that hurt if skipped.

## Per-platform release, added 2026-09-02 (queue R1-M14)

Step 2 ("release devices") had no platform mechanics and no verification criteria (morning-queue
finding). Added a "Release devices, per platform" section, sourced against fleet-v4.90.1:

- **Apple asymmetry**: `DeleteABMToken` (`server/service/apple_mdm.go`, free-tier stub returning
  `ErrMissingLicense`; real implementation `ee/server/service/mdm.go`) only deletes Fleet's local
  token record and flips the app-config flag when the count reaches zero — it never calls Apple.
  Confirmed no Apple API call anywhere in that function. This is why Apple needs two separate
  actions (unenroll/wipe the device, and remove the server assignment in Apple Business itself),
  unlike Android below.
- **Android symmetry**: `DeleteEnterprise` (`server/mdm/android/service/service.go`) calls
  `androidAPIClient.EnterpriseDelete` against Google's API *and* bulk-marks every Android host
  unenrolled in the same call — already documented in this book at 2.12 ("Turning Android MDM off
  deletes your enterprise"), cross-referenced rather than re-explained.
- **ChromeOS and Linux**: no new source research needed. ChromeOS has no MDM surface in Fleet at
  all (confirmed earlier for R1-M6: the extension only calls enroll/read/write, no config-fetch);
  release is entirely a Chrome-policy action in the Google Admin console, per 3.7. Linux has no
  MDM story either, so release is just fleetd/orbit removal (`it-and-security/lib/linux/scripts/uninstall-fleetd-linux.sh`
  in fleet-public: stop+disable the service, remove files, purge the package).
- **Windows and macOS**: cross-referenced this book's own existing content (2.11's "Turning
  Windows MDM off", already covers both halves in one script; 8.4.4's destructive `profiles
  remove` step) rather than duplicating it.

## Fix-loop round (2026-09-02, round3 M19 — Android deletion overclaim)

Android release paragraph said Fleet "deletes the Android Enterprise at Google" and "there is
nothing further to do on Google's side afterward," contradicting this same section's own later
"confirm from the platform's own side" instruction. Re-verified `DeleteEnterprise`
(`server/mdm/android/service/service.go:424-475`): it calls `androidAPIClient.EnterpriseDelete`
against Google's API and only clears local state (`DeleteAllEnterprises`,
`SetAndroidEnabledAndConfigured(false)`, `BulkSetAndroidHostsUnenrolled`) if that call succeeds —
nothing in-tree reads back or confirms the resulting Google-side state. Reworded to "requests
deletion... and clears Fleet's own record" plus an explicit instruction to confirm in the Google
Admin console, consistent with the section's existing platform-confirmation guidance.
## Fix-loop round (2026-09-02, round3 M12 — Linux uninstall script unnamed/unpinned)

Linux release paragraph described removing fleetd generically without naming the script Fleet
actually publishes for this. Confirmed `it-and-security/lib/linux/scripts/uninstall-fleetd-linux.sh`
exists at the tag and matches the described behavior (stop/disable orbit.service, remove files,
purge the distro package). Added the script name, pinned repo path, and both invocation routes
(run as root locally; save as a Fleet script and batch-run per 5.3), matching
`articles/how-to-uninstall-fleetd.md`'s own documented routes.

## Fix-loop round (2026-09-03, round5 C2 — macOS-only `profiles remove` applied to iOS/iPadOS)

The Apple release paragraph led with the destructive `profiles remove` step as the way to
un-enroll "macOS, iOS and iPadOS," but `profiles remove` is a macOS-only host-side command with
no equivalent invocation on iOS/iPadOS, and the chapter never named Fleet's own supported
cross-platform Apple un-enrollment action. Verified against `server/service/mdm.go`'s
`UnenrollMDM` at the tag: its `switch host.Platform` handles `"ios"`, `"ipados"`, and `"darwin"`
identically via `enqueueMDMAppleCommandRemoveEnrollmentProfile`, exposed at the current route
`DELETE /api/v1/fleet/hosts/{id}/mdm` (the older `PATCH .../mdm/hosts/{id}/unenroll` is
deprecated, per `server/service/handler.go`). This is the same per-host "Turn MDM off" action
5.7 already teaches from the host Actions menu. Rewrote the paragraph to lead with that
cross-platform action (cross-ref 5.7) and demote `profiles remove` to an explicitly macOS-only
local fallback with no iOS/iPadOS equivalent.
