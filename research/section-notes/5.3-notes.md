# 5.3 Run and manage scripts, citation ledger

Drafted 2026-08-27 against `fleet-v4.90.1` (dd0200f062).

## Stated

| Claim | Source at the tag |
|---|---|
| Saved scripts are limited to 500,000 characters, ad-hoc scripts to 10,000 | `SavedScriptMaxRuneLen` and `UnsavedScriptMaxRuneLen` in `server/fleet/scripts.go`, applied in the validation path |
| The host terminates a script after five minutes | `MaxHostExecutionTime = 5 * time.Minute` in `pkg/scripts/scripts.go`, with the comment "the maximum time allowed for a script to run in a host before is terminated" |
| The server waits six minutes on a synchronous run | `MaxServerWaitTime = MaxHostExecutionTime + 1*time.Minute`, commented as an allowance for the notification system that delivers scripts |
| The execution timeout is configurable through agent options up to 18,000 seconds | `ScriptExecutionTimeout` in `server/fleet/agent_options.go`, validated against `maxAgentScriptExecutionTimeout = 18000` |
| Output is capped at 10,000 runes and the **end** is kept | `orbit/pkg/scripts/scripts.go`: `const maxOutputRuneLen = 10000`, then `output = output[len(output)-(utf8.UTFMax*maxOutputRuneLen):]`, which slices from the tail |
| Only `.sh`, `.ps1` and `.py` may be uploaded | `server/fleet/scripts.go`, the extension switch and its error: "File type not supported. Only .sh, .py, and .ps1 file types are allowed." |
| Shell scripts must use `/bin/sh`, `/bin/bash` or `/bin/zsh`, optionally under `/usr` | `scriptHashbangValidation`, the anchored regular expression, and `ErrUnsupportedShellInterpreter` |
| Python is supported via `/usr/bin/env python3` or an absolute path to `python` or `python3` | `ErrUnsupportedInterpreter`, whose message enumerates the supported set |
| A result carries an exit code, output and a runtime in seconds | `HostScriptResultPayload` fields set in `orbit/pkg/scripts/scripts.go` when saving |
| A script with a stored exit code is not run again | Same file: the early return when `script.ExitCode != nil`, commented as "already a result stored for this execution" |
| Secret variables are the mechanism for keeping a credential out of stored script content | Established for 5.2, `server/fleet/secret_variables.go` |

## Derived

**"A script is the most powerful thing in Part V and the least constrained."** Editorial, and the
chapter's organising claim.

**"Put your diagnostics at the end."** Follows directly from the verified tail-slicing behaviour.
The advice is mine; the behaviour is source-checked.

**The idempotence guidance** is editorial method, resting on the verified fact that the queue
orders work and does not deduplicate it.

**The secrets-in-output warning.** The mechanism facts underneath are that secrets are substituted
into script content and that output is stored and readable. The conclusion that this is the primary
leak path is my reasoning.

**"Command line arguments are visible on the host."** General operating system behaviour rather
than Fleet behaviour, stated as such. The osquery connection is a cross-reference, not a claim that
Fleet collects command lines by default.

**The library conventions and the pre-flight checklist** are editorial throughout.

## Deliberately not stated

**No claim about which account or privilege level scripts run as.** This is the most consequential
thing a reader would want to know and I could not establish it cleanly for all three platforms at
the tag. Rather than assert it or hedge it into a frequency claim, the chapter says a script can do
"anything the account it runs as can do" and does not name the account. **Flag for a later round.
This is the largest known gap in the chapter.**

**No default value for the agent options script timeout.** The maximum is established. Whether an
unset value falls back to the five minute constant was not confirmed, so the chapter presents the
five minutes as the host limit and the option as a way to raise it, without asserting the default
binding.

**No retry semantics for a failed script.** Whether and when Fleet re-runs a script that failed was
not established. The chapter says a script gets re-run "by a retry" among other causes without
claiming Fleet performs one automatically.

**No Windows or macOS specific execution detail**, such as working directory or environment. The
run directory exists in the source but its guarantees to script authors were not established.

## Boundaries held

Software installation, including installer lifetimes and its own longer timeout, is 5.4. Policy
automation that fires a script is 5.9. The queue and its ordering are 5.1. Secrets as a general
mechanism are introduced in 5.2. Diagnosing a script that never arrived is Part VIII.
