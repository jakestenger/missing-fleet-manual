## Derived

**"Cost is a design decision, not an optimisation."** The organising claim, and editorial.

**The six design habits.** Constraining the expensive table, aggregating on the host and preferring
a cheap table are general osquery practice rather than Fleet behaviour. Presented as habits, not as
rules the product enforces.

**The worked example.** Constructed to demonstrate the mechanisms above rather than transcribed
from a real query. It deliberately names no specific osquery table, because which browser
extension tables exist on which platform is an osquery fact that dates, and the chapter's point
survives without it.

**"The indicator cannot see the tail."** Follows directly from the calculation using p50 only, but
the judgement that this is the important consequence is mine.

**"Denylisting produces a result set biased toward newer hardware."** Follows from denylisting
being per host. The bias framing is derived and is the reason the chapter raises it.

**The data-minimisation habit.** Editorial, not a Fleet mechanism.

## Corrected from the first draft

Six errors the review caught, all now fixed against source:

1. The first draft said 400 rows on three hosts reached the storage threshold. The 1,000-row
   limit is **per host per submission**, so three hosts at 400 rows each are all stored. The
   example was conflating per-host with cumulative.
2. It offered `output_size` as a proxy for nearness to the row threshold. Bytes and rows vary
   independently; the claim is removed.
3. It said denylisting produced "no error, no failure and no Fleet-side signal". There are three
   signals, enumerated above. This was the worst error in the chapter, because it would have sent
   a reader looking in the wrong place.
4. It omitted `shard` and `denylist` entirely, which are the two fields most relevant to a chapter
   about controlling query cost.
5. It declined to state watchdog limits on the grounds that they were osquery's rather than
   Fleet's. They are in Fleet's agent options schema.
6. Its screenshot brief described a per-host statistics table in the interface. No such table
   exists; `denylisted` appears in the frontend only in an interface definition and a mock. The
   brief now targets the performance impact column, which does exist.

## Deliberately not stated

**No units for `system_time` and `user_time`.** The migration types them as `BIGINT UNSIGNED` and
the indicator compares their sum against 2,000 and 4,000, which implies milliseconds, but the tag
does not state it. The chapter gives the thresholds as bare numbers and does not name a unit.
**Flag for a later round** if a source turns up.

**No named osquery tables.** An osquery fact rather than a Fleet one, and one that dates.

**No watchdog default values.** The options are named because Fleet exposes them; the defaults
osquery ships are not asserted.
