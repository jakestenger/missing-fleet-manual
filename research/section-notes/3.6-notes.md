## Stated: ChromeOS

All fresh, from `ee/fleetd-chrome/` at the tag.

| Claim | Source |
|---|---|
| Configuration is `fleet_url` and `enroll_secret` read from Chrome's managed storage | `src/background.ts`: two `chrome.storage.managed.get` calls, each with a build-time constant as its default |
| The extension refuses to run on anything but ChromeOS unless the install type is development | `main()` in `background.ts`: compares `navigator.userAgentData.platform` against `"Chrome OS"` and returns after logging |
| It enrolls at the osquery enrollment endpoint with the enroll secret and the serial, falling back to UUID | `enroll()` in `background.ts` |
| It uses the ordinary distributed read and write endpoints | `live_query()` in `background.ts`. The three endpoints in the file are enroll, distributed read, distributed write, and nothing else |
| **Eleven** tables, implemented in the extension over Chrome enterprise APIs | `src/db.ts` registers eleven `Table` subclasses. The chapter enumerates all eleven, per STYLE §26. The first draft said twelve, counted from the imports rather than the registrations, and was corrected before review |
| A one-minute alarm drives the cycle | `chrome.alarms.create(MAIN_ALARM, { periodInMinutes: 1 })` |
| Published from Fleet's own update URL | `manifest.json` `update_url`, and `updates.xml` |

## Derived

- **"Scheduled reports do not work"** follows from the extension posting to no logging endpoint. Fleet does not state it; the absence in the source is the evidence, and the claim is phrased as what the extension does rather than as a Fleet limitation.
- **"Live reports work"** is worth stating explicitly because 1.2's platform table shows no osquery for ChromeOS, which reads as though nothing can be asked. The distinction is that osqueryd is absent while the osquery *channel* is used.
- **"Pushing it to desktop Chrome does nothing at all, and does it quietly"** is the practical reading of the platform guard.

## Not claimed

- **The extension ID and CRX URL.** Present in the source and deliberately not printed, since a stale identifier in a manual is worse than none and the Admin console flow supplies it.
- **Which Chrome enterprise permissions map to which table.** Not traced.
- **Whether ChromeOS hosts can be targeted by policies or software.** Not established here and not asserted.
- **Google-account-based Android enrollment's expected status.** Consistent with 8.13's handling: record what Fleet shows.
