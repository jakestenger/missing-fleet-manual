# 1.4 notes — The server: MySQL, Redis, and what actually holds state

Verified against: git tag `fleet-v4.90.1` in `~/Source/Fleet/fleet-public`
(branch `manual-verify-4.90.1`). Started 2026-08-20.

Ownership boundary: 8.6 owns diagnostic tables/columns/SQL. 1.4 owns architecture:
what holds which state, why, what it costs, what breaks.

## Findings

### Three stores (docs/Contributing/architecture/high-level-architecture.md, "Storage")
- MySQL: "Primary database for storing configuration, device information, and report results"
- Redis: "Used for caching and managing live report results"
- S3/object storage: "Used for storing software installers and file carve results"
- Diagram: `fleet_server == "Read/Write" ==> db` and `==> redis`. Live query path:
  "server -- 2 put results in Redis --> dbredis".
- Scheduled query results: server -> optional external log destination (not MySQL).

### MySQL version floor (docs/Deploy/Reference-Architectures.md:36, also docs/Get started/FAQ.md:741-743)
- "Fleet requires at least MySQL version 8.0.44, and is tested using the InnoDB storage
  engine with versions 8.0.44, 8.4.8, and 9.5.0. MySQL 9.6.0 is currently incompatible."
- FAQ.md:195 adds: "AWS Aurora requires at least version 3.10.3. Please avoid using MariaDB
  or other MySQL variants that are not officially supported."
- Single writer: Reference-Architectures.md:40 "Fleet supports single-writer database setups:
  one writable primary with read replicas. Multi-writer or group-replication MySQL setups
  are not supported."
- Reference-Architectures.md:160 "**Note: Fleet servers need to talk to a writer in the same
  datacenter. Cross region replication can be used for failover but writes need to be local.**"
- Reference-Architectures.md:158 "In some cases adding a read replica can increase database
  performance for specific access patterns. In scenarios when automating the API or with
  `fleetctl`, there can be benefits to read performance."
- Reference-Architectures.md:27 "Fleet currently has three infrastructure dependencies:
  MySQL, Redis, and a TLS certificate."
- Reference-Architectures.md:46 Redis "to ingest and queue the results of distributed
  queries, cache data, etc."
- AWS sizing tables use Redis 7.x, MySQL 8.0.mysql_aurora.3.08.2, and a
  FLEET_MYSQL_MAX_OPEN_CONNS column per instance size.

### Modular monolith (docs/Contributing/architecture/modular-monolith/README.md)
- 600,000+ LOC across 2,300+ Go files. Transition from layered arch to modular monolith
  with bounded contexts. "The application still deploys as a single binary."
- Only ONE bounded context complete at this tag: **Activity (audit)**, ADR-0007.
- Candidates for future extraction: Identity, Vulnerabilities, Software, Policies,
  Scripts, Reports.
- DB guidelines table: "Single shared database" (all contexts share one MySQL db);
  "Exclusive write ownership" per context; table prefixes; cross-context reads allowed
  (joins permitted but indicate coupling); "No cross-context transactions" - each
  transaction scoped to a single context's tables.
- Enforcement: `arch_test.go` + `server/archtest`, Go `internal/` dirs.
- ACLs at `server/acl/{context}acl/`, e.g. `server/acl/activityacl/`.

### MySQL config (docs/Configuration/fleet-server-configuration.md)
- L18: read replica options mirror primary with `mysql_read_replica_` prefix / YAML section
  `mysql_read_replica`. **"Read replica configuration is fully independent from the primary,
  no values are inherited."** No default for `mysql_read_replica_address`; must be set
  explicitly for Fleet to use a replica. Recommends non-zero
  `mysql_read_replica_conn_max_lifetime` because in some environments the replica address may
  dynamically change (auto-scaling) so idle conns need recycling.
- L212: if a read replica is configured its region must be set explicitly via
  `mysql_read_replica_region`; not inherited.
- `mysql_max_open_conns` default **50**, env `FLEET_MYSQL_MAX_OPEN_CONNS`. Doc guidance: keep
  below the DB's max connection limit; 100 conns available / 3 Fleet servers -> 30.
  Note: Fleet uses SQL prepared statements; MySQL `max_prepared_stmt_count` should be
  >= `FLEET_MYSQL_MAX_OPEN_CONNS * (max number of fleet servers) * 4`. Fleet uses 3 prepared
  statements for auth + 1 additional per connection.
- `mysql_max_idle_conns` default **50**; `mysql_conn_max_lifetime` default **0 (unlimited)**.
- `mysql_sql_mode` default `""`, "should not usually be used".
- AWS reference sizings set FLEET_MYSQL_MAX_OPEN_CONNS 10 (5k/10k hosts), 20 (25k), 25+ larger.

### Redis config (same file)
- `redis_address` default `localhost:6379`. ElastiCache IAM auth only if `redis_region` AND
  `redis_cluster` also set; otherwise falls back to auth without password.
- `redis_duplicate_results` default false: duplicates live query results to a second Redis
  channel named `LQDuplicate` for near real-time export outside Fleet.
- `redis_cluster_follow_redirections` default **true**, cluster only, ignored standalone.
- `redis_cluster_read_from_replica` default **false**, cluster only, ignored standalone.
- `redis_max_idle_conns` default **3**; `redis_max_open_conns` default **0** (no limit);
  `redis_conn_max_lifetime` default 0; `redis_idle_timeout` default **240s**;
  `redis_conn_wait_timeout` default 0 (no wait); `redis_read_timeout` and
  `redis_write_timeout` default **10s** each; `redis_connect_timeout` default 5s.
- `redis_host_cache_enabled` default **true**: "Redis-backed cache that fronts host lookups on
  the osquery and orbit auth paths ... caches authenticated host records in Redis to reduce
  MySQL load on high-volume check-in endpoints."
- `redis_host_cache_ttl` default **60s**, jittered +/-10% to avoid synchronized expiry waves.
  Must be > 0 when host cache enabled.
- `logging_error_retention_period` exists (server error retention) - check default.
- S3: `s3_software_installers_*` and `s3_carves_*` families (bucket, prefix, endpoint_url,
  force_s3_path_style, region, sts_assume_role_arn, cloudfront_url...). `s3_carves_cleanup_*`.
- `allow_missing_migrations` under "## Upgrades".

### Redis cluster is auto-detected, not configured (server/datastore/redis/redis.go:99-116, 392-395)
- `NewPool` builds a `redisc.Cluster` and calls `cluster.Refresh()`. If the refresh error is
  `isClusterDisabled` ("ERR This instance has cluster support disabled" or "NOPERM this user
  has no permissions to run the 'cluster' command") or `isClusterCommandUnknown`, Fleet falls
  back to a standalone pool. Otherwise it uses cluster mode. No `redis_cluster_mode` setting.
  Inferred from source; not documented.
- `clusterPool.Mode()` returns `fleet.RedisCluster`. Cluster mode changes behaviour: multi-key
  commands must hash to one slot, `EachNode` fan-out is needed, PUBLISH subscriber counts
  have to be summed across nodes (redis.go:198-230).

### Recorded server errors (server/errorstore/errors.go)
- Package doc: "store deduplicated instances of errors in an **ephemeral** storage ... keep the
  impact of storage to a minimum (ephemeral data, deduplication, **flush on read**)".
- TTL from `logging_error_retention_period`, default **24h** (config doc L1478-1490).
  0 = keep without expiration; **negative value disables storage of errors in Redis entirely**.
- Retrieve can clear at the same time (flush on read).

### Cron / schedule coordination is MySQL-backed, not Redis (server/datastore/mysql/locks.go)
- `locks` table (name, owner, expires_at). `Datastore.Lock` tries in order:
  `extendLockIfAlreadyAcquired` (UPDATE ... WHERE name=? AND owner=?),
  `overwriteLockIfExpired` (UPDATE ... WHERE expires_at < CURRENT_TIMESTAMP AND name=?),
  `createLock` (INSERT IGNORE). First one affecting a row wins. Unlock sets
  `expires_at = CURRENT_TIMESTAMP`. All against `ds.writer(ctx)`, i.e. the primary.
- Lock expiration = the schedule's interval (`schedule.go:658`
  `s.locker.Lock(ctx, s.getLockName(), s.instanceID, s.getSchedInterval())`).
  `holdLock` renews it while the job runs (schedule.go:679-701).
- `WithAltLockID` lets two schedules share one lock name (schedule.go:120-126).
- `DBLocks` (used by `fleetctl debug db-locks`) reads
  `information_schema.innodb_lock_waits` if present, else
  `performance_schema.data_lock_waits`; requires global PROCESS and SELECT privileges
  (`GRANT PROCESS,SELECT ON *.* TO 'fleet'@'%';`). Deliberately queries the writer,
  "the read replica should have little to no trx locks".

### instanceID (cmd/fleet/serve.go:625-630)
- `instanceID, err := server.GenerateRandomText(64)` then
  `logger.InfoContext(ctx, "instance info", "instanceID", instanceID)`.
  Random 64 bytes, generated fresh **every process start**. Passed to
  `schedule.New(... instanceID ...)`, used as the `locks.owner` and written to
  `cron_stats.instance` (schedule.go:175-188, 744). So the log line and the table column
  are the same value.
- `schedule.go:203` adds `instanceID` to the schedule logger context, so cron log lines
  carry it too.

### Redis-backed lock (server/service/redis_lock/redis_lock.go)
- Separate from the cron lock. "distributed lock using Redis ... to prevent multiple Fleet
  servers from accessing a shared resource." `defaultExpireMs = 60 * 1000`.

### Other Redis-resident state, all with expiry
- SSO session state (server/sso/session_store.go): SAMLRequest ID, IdP metadata, original
  URL, host UUID. "lifetime of the state object is constrained in the backing store (Redis)
  so if the sso process is not completed in a reasonable amount of time, it automatically
  expires and is removed." Consequence: lose Redis mid-login and the login fails.
- Apple MDM profile pre-assign matcher (server/mdm/apple/profile_matcher.go): key prefix
  `mdm:preassign:`, `preassignKeyExpiration = 1 * time.Hour`, external host identifier
  truncated to first 36 runes (`preassignKeySuffixMaxLen`) because in distributed scenarios
  the identifier suffix can vary per server (issue 12483).
- ACME and Platform SSO nonce stores (server/mdm/acme/, server/mdm/psso/).
- IP banner and rate limit store (server/datastore/redis/{ip_banner,ratelimit_store}.go).

### mysqlredis: Redis in front of MySQL (server/datastore/mysqlredis/)
- `enrolled_hosts:host_ids` Redis SET, used only when `enforceHostLimit > 0` (host-count limit
  enforcement). `SyncEnrolledHostIDs` compares DB count to `SCARD`; if they differ it reloads
  IDs from the DB and rebuilds the set. Runs "regularly (via a cron job) so that if the Redis
  set gets out of sync, it eventually fixes itself automatically". `redisSetMembersBatchSize`
  = 10000. Deletes the key when the limit is disabled to reclaim memory.
- Host auth cache: key prefix `fleet:hostcache:v1` (versioned so operators can purge with
  `redis-cli --scan --pattern 'fleet:hostcache:v1:*' | xargs redis-cli DEL`; bumping the
  version orphans old keys which TTL out). `hostCacheNegativeTTL` caps "not found" caching
  at **5s** (comment reasons about DoS/retry protection vs enrollment-race safety).
- Recon cursors for Apple, Apple declarations, Windows, Android reconcilers also live in Redis
  (`*_recon_cursor.go`).

### Migrations (docs/Deploy/Upgrading-Fleet.md, cmd/fleet/datastore.go:79-101, server/fleet/datastore.go:3995-4035)
- `fleet prepare db` runs migrations. Doc: "Database migrations in Fleet are intended to be run
  while the server is offline." "all Fleet instances need to be shut down during the migration
  process. During a typical upgrade, you can expect 5-10 minutes of downtime." "Even on large
  Fleet installations, downtime during migrations is usually only seconds to minutes."
  "Your hosts will buffer any logs generated during this time and send those buffered logs once
  the server is brought online again." Doc advises backing up the DB first.
- Two migration families: `server/datastore/mysql/migrations/tables/` (**575** timestamped
  files at this tag) and `.../migrations/data/` (**9**). Latest is
  `20260723181413_DedupeQueuedVPPAppInstalls.go`.
- Startup gate (`evalMigrationStatus`): `AllMigrationsCompleted` -> start.
  `NoMigrationsCompleted` -> always exit. `SomeMigrationsCompleted` (missing migrations) ->
  print warning and exit unless `allow_missing_migrations` (default false).
  `NeedsFleetv4732Fix` / `UnknownFleetv4732State` -> exit unless allow_missing_migrations.
  `UnknownMigrations` (migrations applied that this binary does not know about, i.e. the DB was
  migrated by a NEWER Fleet) -> prints a message and **returns devMode**, so in production it
  warns and keeps serving; only dev mode exits. Inferred from source.
- `allow_missing_migrations` default false, env `FLEET_UPGRADES_ALLOW_MISSING_MIGRATIONS`.
- Compatibility: Fleet follows SemVer; breaking changes only in major, with three stated
  exceptions (experimental features, security, changes to default values).

### Read replica read semantics (server/datastore/mysql/mysql.go:105-118, server/contexts/ctxdb/ctxdb.go)
- `reader(ctx)` returns `ds.replica` unless `ctxdb.IsPrimaryRequired(ctx)`. `writer(ctx)` is
  always `ds.primary`. So **all reads go to the replica by default**; individual code paths
  opt back into the primary with `ctxdb.RequirePrimary(ctx, true)` when they need
  read-after-write. 34 non-test call sites at this tag, in app_configs, apple_mdm,
  microsoft_mdm, android, jobs, vpp, maintained_apps, users, orbit, appconfig, ee mdm and
  software_installers, nanomdm service, android pubsub.
- `optimisticGetOrInsert` (mysql.go:1264-1305): read id from the replica, insert on the
  primary if missing, on duplicate-key re-read **from the primary**. This is the pattern that
  tolerates replica lag.
- Prepared statement cache "is only available on the replica" (mysql.go:129).
- If no replica is configured `dbReader` is the primary connection (mysql.go:261-283),
  so `reader()` and `writer()` hit the same server.
- Prepared statements consume MySQL resources, limited by `max_prepared_stmt_count`; may create
  1 prepared statement per DB connection (mysql.go:126-131, issue 15476).

### A fourth store: the per-process in-memory cache (server/datastore/cached_mysql/cached_mysql.go)
- `go-cache` in-process, **per Fleet instance, not shared**. Default expirations at this tag:
  AppConfig **1s**, Packs (per host) 1m, ScheduledQueries (per pack) 1m, TeamAgentOptions 1m,
  TeamFeatures 1m, TeamMDMConfig 1m.
- `ctxdb.BypassCachedMysql` marks a context that must not read from this cache, "required when
  reading data with the intention of writing it back with changes, to avoid reading stale data".
- Consequence for multi-instance: a config change is visible on other nodes only after their
  own cache entry expires. Bounded by these TTLs.

### Object storage: configured or node-local fallback (cmd/fleet/serve.go:540-585, cmd/fleet/datastore.go:60-68)
- Carves: `var carveStore fleet.CarveStore = mds` (MySQL) unless `config.S3.CarvesBucket != ""
  || config.S3.Bucket != ""`, in which case `s3.NewCarveStore`. So **carves land in MySQL by
  default**. Config doc for `s3_carves_cleanup_disabled` confirms: "it has no effect when carves
  are stored in MySQL."
- Software installers: with an S3 bucket, `s3.NewSoftwareInstallerStore`,
  `s3.NewBootstrapPackageStore`, `s3.NewSoftwareTitleIconStore` (all in the same bucket, logged
  with the bucket name). Without one, `filesystem.NewSoftwareInstallerStore(installerDir)` where
  `installerDir = os.TempDir()` unless `FLEET_SOFTWARE_INSTALLER_STORE_DIR` is set, and Fleet
  logs at info: **"using local filesystem software installer store, this is not suitable for
  production use"**. If even that fails it installs `failing.NewFailingSoftwareInstallerStore()`.
  Icons similarly honour `FLEET_SOFTWARE_TITLE_ICON_STORE_DIR`.
- `s3_software_installers_bucket` is Fleet Premium and also holds bootstrap packages.
- `s3_carves_prefix`: carve objects are additionally prefixed by date and hour UTC:
  `<prefix><year>/<month>/<day>/<hour>/<carve-name>`.
- `s3_carves_cleanup_max_per_run` default 1000 (bounds HeadObject calls per run).

### Live query results and the Redis pubsub buffer
- docs/Contributing/guides/troubleshooting-live-queries.md:70-72: "Fleet connects to Redis as a
  pubsub client to retrieve results. The results are buffered in Redis up to a limit, default
  value for such limit is `client-output-buffer-limit pubsub 32mb 8mb 60`." Set
  `client-output-buffer-limit pubsub 0 0 0` to remove the limits. "AWS Elasticache Redis has a
  different name for these settings: `client-output-buffer-limit-pubsub-hard-limit`,
  `client-output-buffer-limit-pubsub-soft-limit` and
  `client-output-buffer-limit-pubsub-soft-seconds`."
- Same file, note: "Multiple fleet instances collect results from devices and store them in
  Redis, but when retrieving results via websockets, the browser or fleetctl is connected to
  one Fleet instance."
- FAQ.md:619-623: "Redis has an internal buffer limit for pubsub that Fleet uses to communicate
  query results. If this buffer is filled, **extra data is dropped**." Recommends
  `client-output-buffer-limit pubsub 0 0 60`.

### Async host processing trades MySQL load for Redis load (config doc L1213-1240)
- `osquery_enable_async_host_processing`, **experimental**, default false. Supports
  `label_membership`, `policy_membership`, `host_last_seen`, `scheduled_query_stats`; can be set
  globally or per task (`label_membership=true&policy_membership=true`).
  "may improve the performance and CPU usage of the Fleet instances and MySQL database servers
  for setups with a large number of hosts while **requiring more resources from Redis server(s)**."
- Caveat in the doc: with both the failing-policies webhook and this option on, some webhooks
  could be missed.
- `osquery_async_host_collect_interval` default 30s. "Each Fleet instance will attempt to do the
  collection at this interval (with some optional jitter), with only one succeeding to get the
  exclusive lock."

### /healthz covers both stores (cmd/fleet/serve.go:804-841, server/health/health.go)
- Health checkers registered: `"mysql": ds` and `"redis": resultStore`. `/healthz` returns 200
  if all pass, **500 if any backend reports an issue**. `?check=mysql` or `?check=redis`
  narrows to one checker; an unknown name is a 400.
