## Confirming review, 2026-08-27: READY WITH MINOR CHANGES, applied

Six localised items, five of them the same habit: a claim stated one degree stronger than the evidence.

**The section heading argued with its own table.** "Limits that fail silently" introduced a table containing HTTP 429s, rejected writes and prepared-statement errors, none of which are silent. The honest description is that the failure surfaces somewhere other than where you are looking — at the Redis client, in a status code the UI does not show, in a database error rather than a Fleet one — and that is now the heading and the opening sentence. Some of these are genuinely silent, some are loud in the wrong place, and neither kind is discoverable from the symptom.

**`discard_reports_data` was sold as a relief valve.** "Turning it off does relieve writer saturation" guarantees an outcome; it can reduce writer load where report-result writes are actually implicated, which the reader has to establish first. The one-way framing was also imprecise in a way that matters: the **setting** is reversible, the **deletion** is not.

**`Failed <profile>` was called normal rather than an error.** It is a real per-member collection error that the command tolerates by design, and the difference is the whole point: the archive is written either way, so a partial one looks whole to whoever receives it. Missing database privileges is now the usual cause rather than the only one, since the request can also time out or be refused.

**The carve ceiling is inclusive and binary.** Fleet compares with `>` against `8 * 1024 * 1024 * 1024`, so exactly 8 GiB passes. "under 8GB" was wrong twice over, on the unit and on the boundary.

**Shared database servers** need "more resources" in Fleet's words. The chapter said proportionally more, which is a planning number Fleet does not supply.

**The 25 second deadline is documented after all.** Fleet's REST reference states it, so the mismatch is between two Fleet documents rather than between Fleet and this manual, and only the 90 second write-timeout base is source-only. Worth stating precisely, because "Fleet's docs are wrong here" is a claim this manual makes often enough to owe accuracy about which document.
