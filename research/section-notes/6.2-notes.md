# 6.2 Manage Fleet with GitOps, citation ledger

Drafted 2026-08-28. Process: part-level structure agreed, research consensus in one round, draft, one
review round applied. Working research is held outside this repository, see [`README.md`](README.md).

The chapter's outline came from [`../part6-structure.md`](../part6-structure.md) rather than from a
separate negotiation, which is how Part VI's chapters are being built.

## The organising claim

**`fleetctl gitops` is a client.** It reads YAML, reads live state, computes operations, and performs
them as a sequence of independently committed API calls. There is no server-side GitOps engine, no
repository watcher, and no transaction. Every warning in the chapter is a consequence of that.

The reviewer's phrasing at part level was that a successful invocation is not convergence. This
chapter is where that stops being a slogan.

## Derived

**The four repository invariants.** The framing is mine and the reviewer kept it, but replaced two of
the four. My "production invocations supply the complete file set" and "glob patterns are reviewed"
were one idea stated twice; my "environments are separated by repository or branch" was too weak,
because a branch separates content without binding it to a server. The fourth, that the destructive
fleet-deletion flag belongs only on the canonical complete workflow, was missing entirely and is the
one that prevents the worst outcome.

**The five-step migration.** Export, compare, repair, validate, apply in non-production. The
reviewer's addition was that a staged migration must be a **different invocation** from the canonical
one, because staging supplies a deliberate subset and the canonical workflow's flags would then
delete the fleets not being staged.

**"A dry run is validation. It is not a plan, and it is not a rehearsal."** Editorial, and the
sentence the chapter is most likely to be quoted on.

## Rejected, and why

**My execution order.** Wrong in two ways: it moved an explicit `unassigned.yml` to the end, and it
collapsed conditional restoration, fleet deletion and deferred deletions into a single phase. The
diagram brief repeated the error, so both were replaced.

**"On Premium that deletes the Unassigned scope's software packages."** Unconditional, and the
software exception makes it conditional.

**"Run Fleet Free where it is ignored, and omission deletes them."** Wrong. On a stock Free
installation the secrets exception is still true, so omission still preserves; what differs is that
the inclusion error is Premium-only, so including the key is accepted rather than refused. The
sentence was removed rather than explained, because the asymmetry costs more space than it earns.

**"Records nothing to say a run was in progress."** Contradicted 8.12. Narrowed to no run-level
marker or outcome.

**"Profiles containing a secret variable are dropped from the validation set entirely."** Erased real
client-side validation.

**Four phrases that ran hotter than the part's register**, on the reviewer's advice: "the mental model
most people bring is wrong", "a fair signal of its maturity", "which is what got you here", and "when
the model breaks, which it will". Each is now the operational statement it was decorating.
