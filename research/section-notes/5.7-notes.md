## Derived

**"An action is defined by what it does to the machine. Everything else depends on the platform."**
The chapter's organising claim. Editorial, resting on the verified transport matrix.

**Safety before procedure.** The reviewer agreed and sharpened it: this is not the only destructive
material in the book, since a script or raw command can do as much damage, so the chapter says that
rather than implying wipe is uniquely dangerous.

**"Do not treat a Linux wipe as sanitisation."** The mechanism is source-checked; the instruction is
mine.

**The advice to verify a raw destructive command's outcome on the device.** Follows from C11.

## Rejected, and why

**"Android unlock does not exist."** It does, locally. Only the remote path is absent.

**"Fleet assigns the command identifier."** True of `fleetctl`, false of the direct API.

**"Script-backed actions give you a script exit code and output like any other script."** They do
not; Fleet consumes the result internally.

**"Cancel work you no longer want rather than assuming an unreachable device will never act on it."**
Self-contradictory beside the correct statement that a dispatched command cannot be recalled. The
useful version is that offline time is not a grace period.

**The S3 exposure mechanism.** Deliberately excluded. The chapter says the unlock PIN is credential
material and how to handle it, without describing where it can be read. The reviewer was asked to
argue against the omission, agreed with it, and confirmed on review that the drafted chapter does not
inadvertently point at it. C11 is included by the opposite reasoning: it is a correctness trap an
administrator walks into with legitimate intent, and it confers no new capability.
