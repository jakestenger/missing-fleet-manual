## Derived

**"Installing software is where the interface hides the most."** Editorial, and the chapter's
organising claim. It rests on verified facts about representations and channels, but the framing is
mine.

**The advice to design label scopes to be mutually exclusive.** The precedence rule is verified; the
recommendation not to rely on it is judgement.

**The variant-uninstall safety advice** (make the first-added uninstall script variant-agnostic and
test it, or split into separate titles). The defect is source-checked; the mitigation is mine, and
was endorsed in review as proportionate.

**"Fleet's answer to 'is it installed' and 'did the install succeed' diverge, and both are honest."**
The two generated columns are verified. The framing is mine.

**The secrets warning.** Every mechanism in it is verified: expansion, non-redaction, the reader set,
the device-token path. The instruction to rotate an exposed credential is ordinary security practice
rather than a Fleet behaviour.

**The CDN silence advice.** The fallback and its error behaviour are verified; "that silence is where
to look first" is diagnostic judgement.

## Unverified, and marked as such in the text

**No age expiry for queued software work.** This is a negative result from searching the queue,
cron and installer paths rather than a positive citation. The chapter now says Fleet *defines* no age
expiry at this release, rather than asserting work waits indefinitely, which is what the evidence
actually supports. Flagged in review as an absolute resting on absence; reworded rather than tested.

**Rollback depth.** Verified against the manifest writer and the in-repo fallback tree, where all
1350 manifests carry exactly one version. The primary CDN is outside the tag and cannot be checked
from the repository. The chapter says an evicted version cannot be fetched again **in practice** and
names the mechanism, rather than claiming it is impossible.

**Apple managed-configuration redelivery.** No path re-sends on an Apple configuration change. The
chapter says the new configuration goes out with the next install command and advises triggering a
reinstall if nothing else will, rather than claiming a reinstall is always required, which review
established was too strong.

## Rejected, and why

**The reviewer's round-two rollback qualification.** At outline stage it said deeper rollback is
possible while a version remains published upstream, and I wrote that into the outline. Research then
showed manifests publish only the current version. The reviewer checked and reversed. The
qualification is out.

**A suspected ten-package defect.** The limit count omits `is_active`, which looked as though cached
inactive FMA versions would consume slots. They do not: the count sits behind a custom-package-only
branch. Not mentioned in the chapter.

**"The post-install script runs regardless of the install script's outcome."** Carried in my research
notes on the authority of a Fleet code comment, and wrong. Corrected before drafting.

**Implementation detail deliberately cut**, and endorsed as cut in review: the object-store
configuration matrix, content-addressed storage and garbage collection, magic-byte type detection,
the raw generated-column precedence, `patch_query` internals, and the full error-copy catalogue.
Part VIII owns that altitude.
