## Derived

- **"One channel and no second one to wait for"** as the chapter's frame follows from Linux having no MDM. It is the deliberate inverse of 3.2's and 3.3's two-channel openings.
- **"A headless server can never escrow a key"** follows from the prompt requiring Fleet Desktop and a person, plus 1.2's statement that Desktop does not run without a desktop session. Fleet does not say it in those words.
- **"A configuration-management tool is a good owner of fleetd's configuration on Linux"** follows from the configuration being a plain file the agent re-reads on restart. It is judgement, and it is consistent with 1.1's position on not displacing existing tooling.
- **The half-applied fleetd upgrade** being explained by the missing `systemd-run` is an inference from the fallback branch, not a documented failure mode.

## Errors this chapter found in other chapters

Both were found by `claims.py` and by reading the packager, not by review:

1. **8.2 and 8.4 both described `secret.txt` as the place the enroll secret lands, without platform qualification.** It does not exist on Linux. Both corrected to name `/etc/default/orbit` for that platform, and 8.2's row now says its absence on Linux means nothing at all.
2. Recorded in 8.2's own ledger: the `/var/lib/orbit` symlink claim, which is also a Linux packaging fact.
