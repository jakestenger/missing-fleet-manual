### Corrected: scheduling a report does not build history in Fleet

As published: "Schedule that report to run on a cadence and you build a historical record of how
that state changed across the estate."

`docs/Get started/FAQ.md:405`: "Currently, Fleet only stores the current state of your hosts",
with the recommendation to export via the API or `fleetctl` to maintain history. A scheduled
report delivers results to the configured log destination; the history accumulates there, not in
Fleet. The chapter now says so and points at 2.8, which owns the destination decision.

This appeared in chapter 1.1, describing the product's core value, and an administrator could
have designed a retention approach around it.

Also removed the unqualified "ten thousand machines ... in seconds". Live reports reach hosts
that are online, and response time varies.

interchangeably and called Orbit "Fleet's agent". Vocabulary now established before the
components are described. Orbit is now described as what it is, an osquery version and
configuration manager that also performs host-side work.

## Correction applied 2026-08-27

**The fleetd bundle's contents, and Fleet Desktop's optionality.** The chapter said the bundle contains "osquery, Orbit, and the fleetd Chrome extension", with Fleet Desktop "alongside". Two things wrong with that, both found while applying 3.8's review rather than by reading this chapter:

- **The Chrome extension is not in the bundle.** *Fleetd for Chrome* is a separate browser extension for the one platform where the bundle does not exist, carrying no Orbit, no osqueryd and no Fleet Desktop. Describing it as bundle content implies a Mac's fleetd contains a Chrome extension.
- **Fleet Desktop is inside the bundle and optional**, which is how Fleet's own `high-level-architecture.md` describes it, and `fleetctl package --fleet-desktop` puts it there.

Corrected here, in 1.2, in 3.1 and in 3.8, which had the same two framings between them.

### The correction to my own handoff note

I had written, here and in `HANDOFF.md`, that **"a licence gate presents as an absence rather than as an error, which is why it is guessed at rather than checked"**. The reviewer checked and it is wrong: Fleet's validators return explicit licence errors. Trying the operation and reading the error is the cheapest of the four capability checks, not the most obscure one.

The real reason licence claims keep being wrong is less flattering and worth stating plainly: **the manual asserts them from a general sense of how a product this shape usually gates things, instead of reading the validation.** Corrected in both places.

The licence audit also caught one over-broad gate in the new text: profile *variables* are not a single gate. A Windows profile needs Premium for any Fleet variable, while Apple validates particular variables and certificate references individually.

### A coverage gap found and closed

1.1 and 2.3 both pointed at 2.8 for choosing where osquery results are delivered. **2.8 covered only the activity audit stream**, so neither `osquery_result_log_plugin` nor `osquery_status_log_plugin` was documented anywhere outside Part VIII's diagnostic material. 2.8 now opens with a three-stream table naming all three settings, their defaults, their shared destination list and which of them is Premium, plus the reminder that a result destination still receives nothing from a query whose automations are off.

## Third round, 2026-08-27

NOT READY, eight items. **Three were the reviewer retracting its own round-two claims**, all of which I had written into the chapter on its authority without checking them myself. That is the lesson of this round.

| What round two told me, and I wrote | What is actually true |
|---|---|
| The report row cap "freezes" storage, so hosts that had reported keep their old answer | Much messier. A host whose single snapshot exceeds 1000 rows stores **nothing**; a cleanup job trims across hosts keeping the most recent rows, so an older host's answer can **disappear**; and enabling `query_reports_disabled` **deletes** what is already stored rather than only stopping new writes. The safe conclusion, now in the chapter, is that a clipped report has unknown coverage and unknown freshness |
| Apple validates variables individually rather than gating them all, unlike Windows | **Both platforms gate any Fleet variable on Premium**, from one shared check in `mdm_profiles.go`. Apple's per-variable validation sits on top of that gate, not in place of it. I had written the licence claim in the wrong direction, which is the ninth licence defect and the first that came from trusting the reviewer rather than from guessing |
| Escrowing and rotating the FileVault key is Orbit's work | It crosses all three paths. The MDM profile turns FileVault on and escrows the first key, **osquery** retrieves the encrypted key, and Orbit runs Escrow Buddy only when a rotation is needed |

### The rest

"Everything Fleet holds about a host is the latest thing it reported" was still false: Fleet keeps genuine history for host uptime and vulnerabilities, where a change appends. Scoped to vitals, inventory, policy results and stored report rows.

"Everything Fleet knows about an iPhone arrives through the management protocol" came back, having been fixed in 1.2 and not here: an Apple Business Manager sync creates a pending host row before the device has spoken to Fleet at all.

"Four possible reasons" became "four major checks", since it was an exhaustive claim; "the API is usually explicit" lost its frequency; and the promise that "each feature chapter states its own gate" was fiction, because most of Parts IV and V are still outlines. That last one is now stated as the gap it is.

### The lesson worth carrying

**A reviewer's proposed wording is a claim, not a citation.** Three of this chapter's round-three defects existed because I pasted round two's suggested correction rather than reading the source it pointed at. The reviewer retracted all three itself, which is the system working, but the cheaper path was to have checked them when they arrived. Treat a suggested replacement exactly like your own draft sentence: source it before it lands.
