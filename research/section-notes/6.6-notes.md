# 6.6 Connect an AI assistant to Fleet, citation ledger

Drafted 2026-09-01. Source is `cmd/fleet-mcp` at tag `fleet-v4.90.1` (commit `dd0200f062`), read directly, plus the tool's own `README.md` at that tag. The server is distributed inside `fleetdm/fleet` and is not independently tagged, so "the tag" here means the Fleet release tag the monorepo carried it under. Working research is held with this file.

Every row is marked **Stated** (the Fleet/MCP source at the tag says this), **Derived** (concluded from what the source says, reasoning given), or **Unverified** (could not be established at the tag).

## Stated: verified at the tag

| Claim | Basis |
|---|---|
| The server is a stateless proxy that holds one Fleet API token and turns each tool call into Fleet REST API calls with that token; Fleet authorizes every call | `NewFleetClient` + the domain tool files call `makeFleetRequest` with the single configured key; no local store |
| Two transports, **stdio** (subprocess over stdin/stdout) and **SSE** (HTTP), with the same tool surface | `main.go` transport switch; `SetupMCPServer` registers the same tools regardless of transport |
| The server refuses to start unless `FLEET_API_KEY` belongs to an **API-only** Fleet user, checked via `GET /api/v1/fleet/me`, and **fails closed** if Fleet is unreachable or the token invalid | `requireAPIOnlyUser` in `main.go`; `WhoAmI` reads `api_only` from `/me`; both failure paths call `logrus.Fatalf` |
| `MCP_AUTH_TOKEN` is **required on every transport including stdio** and must be **≥ 32 chars**, else the server refuses to start | `main.go` startup validation; `minMCPAuthTokenLen = 32` |
| `MCP_AUTH_TOKEN` is compared in **constant time** on SSE requests | `bearerAuthMiddleware` uses `crypto/subtle.ConstantTimeCompare` |
| SSE speaks **plain HTTP**; TLS must be terminated in front | `main.go` builds an `http.Server`, no TLS config; README security model |
| `FLEET_TLS_SKIP_VERIFY` is **hard-gated to loopback** (`localhost` / `127.0.0.1` / `::1`) and refuses to start with a non-loopback URL; mutually exclusive with `FLEET_CA_FILE` | `NewFleetClient` + `isLoopbackURL` in `fleet_integration.go` |
| **One tool is marked destructive** (`run_live_query`); every other tool is marked read-only. The annotations are **advisory hints to a cooperating client**, not a server-enforced control | `WithDestructiveHintAnnotation(true)` on `run_live_query` only, in `mcp_tools_queries.go`; the enforcement note is in `mcp_server.go`'s comment on `fleetMCPInstructions` |
| The real write boundary is the **token's Fleet role**: observer reads work, `run_live_query` needs observer-plus or higher, no maintainer/admin required | README security model; `mcp_server.go` comment ("observer token => Fleet 403s the writes"); Fleet RBAC |
| **Schema-first live query**: the client is instructed to fetch the schema, then run SQL, and the server validates SQL against canonical column types, rejecting text-vs-bare-integer comparisons | `fleetMCPInstructions` in `mcp_server.go`; `ValidateSQLForPlatforms` in `schema.go` |
| The osquery schema is held **in memory**, refreshed in the background from Fleet's published schema JSON on `raw.githubusercontent.com` | `StartSchemaRefresh` wired in `SetupMCPServer`; README schema section |
| **Query-first host resolver**: a numeric `host_id` goes straight to `/hosts/:id`; a name that matches several hosts returns a candidate list for disambiguation | README hosts section + operational learnings; `mcp_tools_hosts.go` |
| Live query is an **ad-hoc campaign** bounded by a wait (`FLEET_LIVE_QUERY_REST_PERIOD`, default `25s`), returning early once all online hosts answer; offline hosts are absent, not queued | README configuration + `run_live_query`; `live_query_campaign.go` |
| **Temporary saved queries** (`fleet-mcp-temp-` prefix) are created per live query and deleted on completion; leftovers are swept at the next start | README security model (saved-query sweeper) |
| Input validation at the server: `cve_id` matches `^CVE-\d{4}-\d{4,}$`, `policy_id` positive integer, `policy_response` requires `policy_id`, `per_page` clamped to 200 | README security model; `mcp_helpers.go` validators |
| SSE request bodies capped at **1 MiB**; `ReadHeaderTimeout=10s`, `ReadTimeout=30s`, `IdleTimeout=120s` | `main.go` `maxRequestBodyBytes` + `http.Server` timeouts |
| Unauthenticated **`/healthz`** liveness probe returns `200`; route guard passes only `/sse` and `/message` | `healthzHandler` + `mcpRouteGuard` in `main.go` / `route_guard.go` |
| Inventory tools read **stored inventory** (refreshed at check-in) and answer for offline hosts, unlike a live query | README inventory section |
| Claude Desktop reads env from its **JSON config, not `.env`**; Apple Silicon needs an **ad-hoc signature after every rebuild** or the launch fails | README stdio + operational learnings |
| Builds against **Go 1.25.7**; the binary carries no release tag of its own | README prerequisites; `go.mod` |

## Derived

**"Read-only is not the same as harmless."** The chapter's organising security claim. `run_live_query` runs arbitrary osquery on devices; the README notes tables such as `curl` / `curl_certificate` / `carves` can make outbound requests or read file content. The inference the chapter draws — that an observer token is the enforced way to remove the capability, because Fleet 403s the write — is stated in source; the framing that the client's confirmation prompt is *not* the real control is derived from the advisory-hint comment.

**"The MCP is a proxy, so diagnosis is diagnosis of the Fleet API path."** Concluded from the stateless-proxy structure, not a sentence in the source. It is the basis for the short Part VIII handoff.

**Some answers are composed across several Fleet calls because a single filter cannot be trusted.** Derived from the README operational-learnings section and the presence of `GetHostsForCVE` / label-intersection compose paths in `fleet_integration.go`. See the lead below — the *reason* (Fleet ignoring the filters) is asserted by Fleet's own code but not independently reproduced here.

## Unverified — leads, not claims

- **Fleet's `GET /hosts` silently ignoring `cve` / `platform` / `label_id` filters, and `?cve=` returning wrong results.** The MCP's own source and README assert this ("as of Fleet 4.85") and deliberately route around it (`GetHostsForCVE`'s 3-step compose; label/platform via `/labels/:id/hosts`). I verified the **workaround exists in source at the tag**; I did **not** independently reproduce Fleet returning the wrong host set, which needs a running Fleet. If real at 4.90.1 this is a Fleet code defect worth a `C` entry in the defect queue — flagged for Jake rather than filed at the queue's "verified independently" bar. The chapter states only that the tool returns the right hosts, which is safe.
- **Exact per-tool argument lists.** Routed to `a.8` rather than enumerated in the chapter; not re-verified argument by argument here.
