## Corrected at Codex round 4 (2026-09-01)

- **Edition-aware roles.** The blanket "observer-plus, no admin/maintainer required" is Premium-only. Verified at the tag: an API-only user can be created on Free (core integration suite, `TestCreateAPIOnlyUser`, returns OK; empty `APIEndpoints` = full access); `api_endpoints` allowlists are rejected without Premium (core suite); observer-plus and team-scoped API users are Premium (reviewer-cited integration tests). So: read-only observer works on either edition; live queries need observer-plus (Premium) or a maintainer/admin identity (Free); team scope and endpoint allowlist are Premium; the API-only requirement itself holds on both. Reflected in the security section and version notes. **The MCP does not require Premium** — an important thing to have got right, since the API-only user it depends on is Free-available.
- **Shared-secret boundary.** One server process carries one bearer and one Fleet identity, so the SSE bearer is a shared secret, not per-user login: every holder has the same scope, all activity attributes to the same API-only user, and the server cannot revoke or throttle a single client. Added, with the recommendation to run one identity per trust group or front it with an identity-aware gateway. Softened the body-cap/timeout claim — those are not rate limiting, which belongs at the edge.
- **Completeness ceilings.** "Sample" → "partial first page"; noted that an aggregate that fetches hosts internally stops at a 10,000-host ceiling and reports a lower bound past it, and that a filtered live query previews at most 100 of up to 500 resolved targets. Source-checked by the reviewer.
- **Meta-prose.** Removed "…is in the right place", "what makes the rest trustworthy", and "the boundaries that decide whether an answer is complete".

Kept "Edge cases and precedence" as the heading (the book's standard §4/template section) rather than fragmenting into per-topic headings as the reviewer suggested.

## Derived

**"Read-only is not the same as harmless."** The chapter's organising security claim. `run_live_query` runs arbitrary osquery on devices; the README notes tables such as `curl` / `curl_certificate` / `carves` can make outbound requests or read file content. The inference the chapter draws — that an observer token is the enforced way to remove the capability, because Fleet 403s the write — is stated in source; the framing that the client's confirmation prompt is *not* the real control is derived from the advisory-hint comment.

**"The MCP is a proxy, so diagnosis is diagnosis of the Fleet API path."** Concluded from the stateless-proxy structure, not a sentence in the source. It is the basis for the short Part VIII handoff.

**Some answers are composed across several Fleet calls because a single filter cannot be trusted.** Derived from the README operational-learnings section and the presence of `GetHostsForCVE` / label-intersection compose paths in `fleet_integration.go`. See the lead below — the *reason* (Fleet ignoring the filters) is asserted by Fleet's own code but not independently reproduced here.

## Unverified — leads, not claims

- **Fleet's `GET /hosts` silently ignoring `cve` / `platform` / `label_id` filters, and `?cve=` returning wrong results.** The MCP's own source and README assert this ("as of Fleet 4.85") and deliberately route around it (`GetHostsForCVE`'s 3-step compose; label/platform via `/labels/:id/hosts`). I verified the **workaround exists in source at the tag**; I did **not** independently reproduce Fleet returning the wrong host set, which needs a running Fleet. If real at 4.90.1 this is a Fleet code defect worth a `C` entry in the defect queue — flagged for Jake rather than filed at the queue's "verified independently" bar. The chapter states only that the tool returns the right hosts, which is safe.
- **Exact per-tool argument lists.** Routed to `a.8` rather than enumerated in the chapter; not re-verified argument by argument here.

## Rejected, and why (Codex round 1, 2026-09-01)

The independent review (`reviews/2026-09-01/6.6-sol.out`, verdict NOT READY) caught four factual defects, three source-checked at the tag. All came from trusting the tool's bundled `README.md` over the Go source — the lesson §27 already records, that a `stated` row cites Fleet's source at the tag and nothing else, including not the tool's own prose.

- **"Temporary saved queries (`fleet-mcp-temp-` prefix) swept at startup."** Not in the tagged MCP source at all. `CreateSavedQuery` exists only for `-seed` mode; live queries use the ad-hoc host-query and unsaved-campaign paths above. The README's "saved-query sweeper" bullet describes behaviour the code does not have. Removed from the chapter.

Corrected to distinguish attribution from completeness, and to name the MCP server logs as the record of read-tool calls.

Also fixed at round 1: the a.8 handoff (a.8 is REST routes, not MCP tool arguments — now points to the tagged `cmd/fleet-mcp` for arguments), the architecture diagram brief (now shows separate stdio/SSE branches and the auth boundary), removal of the volatile Claude Desktop screenshot, and a narrative-cadence pass removing announce-the-next-move transitions and de-duplicated edge cases.
