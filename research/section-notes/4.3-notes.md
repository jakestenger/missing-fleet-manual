# 4.3 Use policies for compliance, citation ledger

First draft, 2026-08-27, against `fleet-v4.90.1` (dd0200f062).

## Stated

| Claim | Source at the tag |
|---|---|
| A policy result per host is passing, failing, or absent | `server/datastore/mysql/schema.sql`, `policy_membership.passes` is `tinyint(1) DEFAULT NULL`, so the third state is stored rather than inferred |
| A policy passes when its query returns rows and fails when it returns none | Fleet's policy evaluation records `passes` from whether the query produced rows |
| Policies run on `osquery.policy_update_interval`, default one hour | `server/config/config.go` |
| Jitter of up to ten percent by default | `server/config/config.go`, `osquery.max_jitter_percent` default 10 |
| The host record carries `policy_updated_at` separately from `detail_updated_at` and `seen_time` | `server/fleet/hosts.go`, the `Host` struct |
| Policy passing and failing counts are stored with their own timestamp | `server/fleet/policies.go`: `PassingHostCount`, `FailingHostCount`, `HostCountUpdatedAt` |
| The policy platform selector takes the generic values | `server/fleet/policies.go` validates against `darwin`, `windows`, `linux`, `chrome`; established in 1.3 that Linux-family hosts map to `linux` |
| A global policy applies to hosts in every fleet | `server/datastore/mysql/policies.go`, the selection accepts `p.team_id IS NULL OR p.team_id = ...`; established while correcting 1.3 |
| Policies support all four label modes, one include and one exclude together | `server/fleet/policies.go`, `verifyPolicyLabelScopes` |
| Label targeting on policies is Fleet Premium | `server/service/global_policies.go` and `server/service/team_policies.go` return `ErrMissingLicense` when any label list is non-empty without Premium |
| Policies carry a resolution and a critical flag | `server/fleet/policies.go`, `Resolution` and `Critical` on `PolicyData` |
| A policy can carry a software-install or script automation, on fleet policies | `server/fleet/policies.go`, `SoftwareInstallerID` and `ScriptID`, with the comment "Only applies to team policies" |
| Continuous automations are Fleet Premium | `server/service/global_policies.go`: `if policy.ContinuousAutomationsEnabled && !license.IsPremium(ctx)` returns `ErrMissingLicense` |
| Policies have no label freshness guard | Established while correcting 1.3: the profile and software queries compare `label_updated_at` against the label's creation time and the policy selection does not |

## Derived

**"Read passing plus failing against your total."** The three states are source-backed; presenting the remainder as the population worth asking about is the chapter's argument and the reason it leads with the three states rather than two.

**"Write the query for the good state."** Follows directly from pass meaning rows returned, but stating it as an instruction is editorial, and it is the single most useful sentence in the chapter for a new author.

**The reading-honestly table.** Each row rests on a source-checked fact above; the selection and ordering are editorial.

## Deliberately not stated

**No licence gate is claimed for the `critical` flag.** I looked and did not find one, and Fleet's Premium markers around "critical" in the documentation attach to *vulnerability* severity rather than to the policy flag. Rather than assert either way, the chapter describes the flag without a tier. This is the discipline the Part I reviews forced: nine licence claims were wrong before I started checking each one against its own validation.

**No claim about how automations behave beyond the three facts that change how the policy page reads.** Attaching and operating them is 5.7's, and this chapter says so rather than half-covering it.
