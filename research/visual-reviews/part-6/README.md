# Part VI visual candidates

Eleven candidates: ten new editable SVG diagrams and one built-in image-generation replacement for the seven-sender comparison. All await the final collection review. Published prose and images are unchanged; the Part V authentic screenshot blocker remains separate.

Run `python3 research/visual-reviews/part-6/render-diagrams.py` to render the native candidates with the Part 0–1 primitives. Requires Inter, Roboto Mono, rsvg-convert and cwebp. Complete raster prompts and selected master are recorded in raster-prompt-history.json and raster-selections.json. Current chapter briefs are in briefs.json.

The diagrams preserve client/server boundaries, uncertain-write reconciliation, partial GitOps state, token-assignment restoration conditions, per-route prefixes, host-list cursor traversal, whole-file configuration races, client exit-status semantics, receiver-owned durable intake, and separate MCP credentials. The receiver design explicitly decides whether an effect is needed; repeated delivery is not automatically discarded or treated as permission to repeat the effect.

Three legacy briefs were revised to fit the produced layouts. The GitOps diagram uses readable ordered phases and states that one file may require multiple independently committed API requests. Its tall layout shows the failed invocation and deferred work without tiny labels; assess its final page placement during joint review. The prefix diagram focuses on its two concrete route examples and omits a redundant generic third band. The exit-status diagram folds the numbered server-backed example and keeps ignored delete kinds in a detached client-only exception card, so that no-op is never routed through Fleet or through an invented printed result. The assignment-window wording now says that assignment lists are temporarily cleared, with the new-fleet condition in the subtitle.

The prefix example received a pinned source spot check in fleet-v4.90.0: server/service/handler.go registers core versions v1 and 2022-04 and starts policy routes at 2022-04; server/activity/internal/service/handler.go registers v1 and latest; server/platform/endpointer/endpoint_utils.go adds latest for eligible routes and builds a registered versioned path. Other figures were checked against their current chapters. This is not a fresh whole-release audit.

All ten native diagrams were inspected at 720 px. Grayscale spot checks covered assignment loss, module prefixes and MCP boundaries. Review removed crossing labels, rejected-page connectors overlapping cursor paths, and ambiguous receiver routing. The raster replacement was checked for request/response directions, separate optional polling, receiver ownership, and the limits on recovering persistent conditions; duplicate step labels and overwide ownership bands were corrected. Raster typography and the tallest layouts remain part of final print-size review.
