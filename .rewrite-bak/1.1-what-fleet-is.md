# What Fleet is

Fleet is an endpoint management platform for seeing the state of devices, deciding which
devices need attention, and making controlled changes across an estate. It brings endpoint
operations, security, and infrastructure automation into one control plane.

Fleet helps administrators answer three practical questions:

1. **What is on this device, and what is its current state?**
2. **Which devices need a configuration, remediation, or software change?**
3. **How can we make and audit that change across the estate?**

It answers them with osquery-based device data, host management through fleetd, and the
device-management protocols available on each operating system.

## What Fleet enables

| Need | Fleet capability | Typical outcome |
|---|---|---|
| Understand device state | Host vitals, software inventory, live and scheduled queries, reports | Find devices with a particular application, user, configuration, or security condition |
| Make a decision | Labels, policies, fleets, and vulnerability information | Identify the devices that need attention and scope a rollout |
| Change device state | Software, scripts, profiles, MDM commands, OS settings, and encryption workflows | Deploy an application, apply a setting, or support a recovery workflow |
| Automate administration | GitOps, fleetctl, REST API, policy automations, and integrations | Make administration reviewable and repeatable |
| Run at enterprise scale | Agent channels, update controls, audit history, logs, and server operations | Operate a consistent endpoint-management service |

The rest of this manual follows that progression: connect devices, understand them, manage
them, automate the work, and operate the service.

## Fleet in your environment

Fleet works alongside the systems an organization already uses:

| System | How it works with Fleet |
|---|---|
| Identity provider | Authenticates administrators and can provide identity context for device workflows |
| Configuration-management tools | Continue to manage infrastructure configuration where they are already the right owner, especially for Linux |
| SIEM, data lake, and security tools | Receive Fleet data, logs, audit records, and other signals for longer-term analysis and response |
| Apple MDM, Windows OMA-DM, and Android Management API | Provide the platform-native management paths that Fleet coordinates |
| IT asset systems | Can consume Fleet’s current device facts alongside the organization’s ownership and lifecycle records |

This integration model lets Fleet fit into an existing operating model while giving endpoint
teams a common view of hosts and management work.

## Platform capability starts with the available path

Fleet provides a consistent administrative experience where possible, while using the
mechanism each platform makes available.

| Device class | Device-data path | Device-management path | What this enables |
|---|---|---|---|
| macOS | fleetd and osquery | Apple MDM | Inventory, queries, scripts, software, profiles, and MDM commands |
| Windows | fleetd and osquery | Windows OMA-DM | Inventory, queries, scripts, software, profiles, and MDM commands |
| Linux | fleetd and osquery | Agent management | Inventory, queries, scripts, software, and Linux-specific workflows |
| iOS / iPadOS | MDM-reported inventory | Apple MDM | Apple device-management actions and inventory |
| Android | AMAPI-reported inventory | Android Management API | Android policy, managed applications, and supported device data |
| ChromeOS | Fleet Chrome extension | Extension management | Fleet’s ChromeOS management capability |

The platform chapters in Part III explain enrollment and prerequisites. Feature chapters explain
the platform differences that change an administrator’s decision.

## A useful mental model

Think of Fleet as a control plane with several device-side executors:

- **osquery** observes and queries hosts.
- **Orbit** runs Fleet’s agent-side work.
- **Fleet Desktop** gives a logged-in user a Fleet surface when that is useful.
- **The OS MDM client** applies profiles and MDM commands on supported platforms.
- **The Fleet service** stores desired state, receives results, and coordinates work.

These components work together through clear channels and responsibilities. The next chapter
explains that model and shows how it supports day-to-day administration.
