# Connect certificate authorities

![Explanation](../_assets/icons/explanation-light.svg) Connecting Fleet to your certificate authority lets supported configuration profiles obtain the certificates devices need for services such as Wi-Fi or VPN access. It brings certificate delivery into the same rollout as the settings that use it. Configure the issuing authority before deploying a profile with its Fleet variables; profiles without certificate variables need no CA connection.

## Purpose and scope

![Explanation](../_assets/icons/explanation-light.svg) This chapter explains the six authority types, the information each connection needs, and how Fleet validates and protects that information. It then follows certificate delivery to a host and shows how to verify issuance. [5.2](../05-manage-devices/5.2-manage-configuration-profiles-and-declarative-settings.md) covers authoring the profiles that use these connections.

Okta conditional access uses a separate, locally generated CA and certificate records. It does not use the authorities connected here; see [2.5](2.5-identity-providers-sso-scim-and-role-sync.md).

## Prerequisites: a server private key, and Premium

![How-to](../_assets/icons/howto-light.svg) Prepare the server private key and Premium license before connecting an authority. Both are needed for the supported certificate-delivery workflow.

**Configure the server private key.** Fleet requires it to create authorities, encrypt stored credentials, and enable the delivery proxy. It also gates conditional access ([2.5](2.5-identity-providers-sso-scim-and-role-sync.md)). Set it in server configuration and restart Fleet.

**Certificate-authority operations require Premium:** connecting, reading a full record, updating, deleting, and test-issuing. The host-facing SCEP proxy is registered only at a Premium server startup. GitOps has two exceptions:

- **The GitOps read-back is not licence-gated.** A `GET` of the GitOps certificate-authorities spec runs on Free, so a read of current state succeeds where a write would be refused.
- **A Free GitOps apply that names only a custom EST or a Smallstep authority reports success and creates nothing.** The emptiness test that is meant to reject the write on Free was written before those two types existed and does not count them. A request carrying only EST or Smallstep authorities, or no authorities at all, is accepted, applies nothing, and returns green. A Free apply that adds an NDES, DigiCert, custom SCEP, or Hydrant authority is rejected as expected. Read a green Free GitOps run that mentions only EST or Smallstep as having done nothing, not as having succeeded.

![Reference](../_assets/icons/reference-light.svg) Fleet speaks to six kinds of authority, and they fall into three families by protocol. Microsoft's **Network Device Enrollment Service (NDES)**, custom **Simple Certificate Enrollment Protocol (SCEP)**, and Smallstep are SCEP proxies: Fleet stands between the host and your SCEP endpoint. Hydrant and custom **Enrollment over Secure Transport (EST)** are EST-based. DigiCert is its own REST API. The family decides how a certificate is later delivered.

Authority names must contain only letters, digits, and underscores, with 1–255 characters. DigiCert, custom SCEP, and Smallstep use the name in profile variables. Hydrant and custom EST follow the same naming rule even though they have no profile variables.

| Type (config value) | What you supply | Secret | Family |
|---|---|---|---|
| **DigiCert** (`digicert`) | `name`, `url`, `api_token`, `profile_id`, `certificate_common_name`, `certificate_user_principal_names`, `certificate_seat_id` | `api_token` | REST API |
| **NDES SCEP** (`ndes_scep_proxy`) | `url`, `admin_url`, `username`, `password` | `password` | SCEP proxy |
| **Custom SCEP** (`custom_scep_proxy`) | `name`, `url`, `challenge` | `challenge` | SCEP proxy |
| **Smallstep** (`smallstep`) | `name`, `url`, `challenge_url`, `username`, `password` | `password` | SCEP proxy |
| **Hydrant** (`hydrant`) | `name`, `url`, `client_id`, `client_secret` | `client_secret` | EST |
| **Custom EST** (`custom_est_proxy`) | `name`, `url`, `username`, `password` | `password` | EST |

**NDES** permits one connection with the fixed name `NDES`, reserved from use by other types. It takes no `name` field. Other types support multiple named connections.

The REST endpoints that create, list, read, update, delete, and test-issue authorities are catalogued in [a.8](../09-appendices/a.8-api-action-and-endpoint-reference.md); the `certificate_authority` permission that governs them is in [a.4](../09-appendices/a.4-roles-and-permissions-matrix.md).

## What creation validates, and what it does not

![Explanation](../_assets/icons/explanation-light.svg) Connecting an authority makes a live outbound request from Fleet. This checks that the endpoint is reachable and speaks the expected protocol. Some authority types also validate credentials at this stage; others need a separate issuance test.

For three types the live check also exercises the credentials you supplied:

- **DigiCert** performs an authenticated profile lookup, so a bad API token or an unknown profile ID is caught at connect time.
- **NDES** exercises both the SCEP URL and the admin URL, distinguishing a full password cache, insufficient permissions, and bad credentials.
- **Smallstep** exercises the SCEP URL and its separate challenge URL.

For the other three types, test issuance to confirm the credentials as well as the connection:

- **Hydrant** and **custom EST** fetch the authority's certificate over an unauthenticated call. That call does not use the username, password, client ID, or client secret you supplied, so those are validated for shape but not for correctness.
- **Custom SCEP** fetches the authority's certificate but does not test the issuance challenge you configured.

A successful connection establishes reachability and protocol compatibility. Custom SCEP’s challenge is first exercised when a host requests a certificate. Hydrant and custom EST exercise their credentials only through test-issue requests; neither delivers to hosts at this release.

## Where Fleet keeps the credentials

![Explanation](../_assets/icons/explanation-light.svg) Fleet encrypts each authority’s secret in MySQL with the server private key: the token, password, challenge, or client secret. URLs, profile ID, common name, seat ID, client ID, and username remain in clear text.

Reading a secret back out through the API is a separate, higher permission than reading the record, so an operator who can see that an authority exists cannot necessarily retrieve the token behind it.

Use the variables for your authority type. `<CAName>` is the configured name, using letters, digits, and underscores.

| Authority | Profile variables |
|---|---|
| NDES | `$FLEET_VAR_NDES_SCEP_CHALLENGE`, `$FLEET_VAR_NDES_SCEP_PROXY_URL` |
| Custom SCEP | `$FLEET_VAR_CUSTOM_SCEP_CHALLENGE_<CAName>`, `$FLEET_VAR_CUSTOM_SCEP_PROXY_URL_<CAName>` |
| Smallstep | `$FLEET_VAR_SMALLSTEP_SCEP_CHALLENGE_<CAName>`, `$FLEET_VAR_SMALLSTEP_SCEP_PROXY_URL_<CAName>` |
| DigiCert | `$FLEET_VAR_DIGICERT_DATA_<CAName>`, `$FLEET_VAR_DIGICERT_PASSWORD_<CAName>` |

For automatic renewal on supported proxied SCEP paths, include `$FLEET_VAR_CERTIFICATE_RENEWAL_ID` in the certificate subject. `$FLEET_VAR_SCEP_RENEWAL_ID` is its legacy alias. Fleet substitutes a profile marker and matches it against certificates reported by the host to manage renewal.

- **Apple:** put the variable in the SCEP or ACME payload’s common name or organizational unit.
- **Windows:** put it in `OU=`. Use `$FLEET_VAR_SCEP_WINDOWS_CERTIFICATE_ID` in `CN=` to identify the certificate.

The renewal variable supports NDES, custom SCEP, and Smallstep where the platform supports that family. It requires the matching SCEP URL and challenge variables; Fleet rejects a profile missing them. Omitting the renewal variable allows issuance but leaves the certificate outside automatic renewal.

**SCEP delivery:** the host enrolls against Fleet’s proxy, which relays to the upstream authority and returns its certificate. Challenge handling differs:

- **Custom SCEP** puts the static upstream challenge you configured into the profile, and encodes a separate, Fleet-generated one-time challenge into the proxy URL. Fleet consumes that URL challenge once.
- **NDES** and **Smallstep** fetch the upstream challenge live and insert it into the profile, and their proxy URL carries no Fleet one-time challenge. Instead the proxy checks the age of the recorded challenge and may ask for the profile to be resent.

**DigiCert issues server-side and ships the certificate inside the profile.** Fleet requests the certificate from DigiCert itself, embeds the returned PKCS12 blob into `$FLEET_VAR_DIGICERT_DATA_<CAName>`, and puts a random password into `$FLEET_VAR_DIGICERT_PASSWORD_<CAName>`. The host never contacts DigiCert; the certificate arrives inside the profile it already receives.

**Which platforms each path serves.** The Apple configuration-profile path resolves all four delivery-capable types: NDES, custom SCEP, Smallstep, and DigiCert. Windows delivers NDES and custom SCEP through its own resolver, addressed by the Windows SCEP certificate identifier variable. Android delivers custom SCEP, referenced from its policy rather than from an uploaded profile ([2.12](2.12-bind-android-enterprise.md), [3.6](../03-connect-devices/3.6-enroll-android-devices.md)). Smallstep and DigiCert are established end-to-end on the Apple path at this release; do not assume they behave identically on Windows or Android without checking.

**Hydrant and custom EST** support synchronous test issuance only. Submit a CSR to receive PEM or PKCS7; the endpoint rejects other CA types. It returns a certificate to the caller without deploying it to a managed host.

## The GitOps representation

![How-to](../_assets/icons/howto-light.svg) In GitOps, authorities live under `org_settings.certificate_authorities`, grouped by type. NDES is a single object because there is only ever one; every other type is a list. The field names are the ones from the type table.

```yaml
org_settings:
  certificate_authorities:
    ndes_scep_proxy:            # a single object, not a list
      url: https://ndes.example.com/certsrv/mscep/mscep.dll
      admin_url: https://ndes.example.com/certsrv/mscep_admin/
      username: fleet-ndes
      password: $NDES_PASSWORD          # secret
    digicert:
      - name: MyDigiCert
        url: https://one.digicert.com
        api_token: $DIGICERT_API_TOKEN  # secret
        profile_id: abc123
        certificate_common_name: $FLEET_VAR_HOST_HARDWARE_SERIAL
        certificate_user_principal_names:
          - $FLEET_VAR_HOST_END_USER_EMAIL_IDP
        certificate_seat_id: $FLEET_VAR_HOST_END_USER_EMAIL_IDP
    custom_scep_proxy:
      - { name: MyCustomSCEP, url: https://scep.example.com/scep, challenge: $SCEP_CHALLENGE }
    smallstep:
      - { name: MySmallstep, url: https://ca.example.com, challenge_url: https://ca.example.com/challenge, username: fleet, password: $SMALLSTEP_PASSWORD }
    hydrant:
      - { name: MyHydrant, url: https://hydrant.example.com/est, client_id: fleet, client_secret: $HYDRANT_SECRET }
    custom_est_proxy:
      - { name: MyEST, url: https://est.example.com/.well-known/est, username: fleet, password: $EST_PASSWORD }
```

Keep the secret values out of the file. `fleetctl generate-gitops` emits this block for an existing deployment with each secret replaced by a placeholder, so you can capture what you have without committing a credential.

Move legacy `ndes_scep_proxy`, `digicert`, and `custom_scep_proxy` blocks from `org_settings.integrations` to `org_settings.certificate_authorities`. The old keys cause an apply error; Fleet does not migrate them automatically. See [6.2](../06-automate-fleet/6.2-manage-fleet-with-gitops.md) for CA reconciliation.

## Verification and ownership

![How-to](../_assets/icons/howto-light.svg) Test issuance after connecting an authority; creation alone may not exercise its credentials.

1. **Connect the authority and read the record back.** A clean create means Fleet reached it. Every successful connection also writes an activity record, so the connection is auditable ([1.5](../01-foundations/1.5-audit-and-activity.md), [8.12](../08-troubleshooting/8.12-audit-logs.md)).
2. **Issue one certificate end to end.** For a delivery-capable type, scope a test profile carrying the authority's variable to one host and watch the certificate install ([5.2](../05-manage-devices/5.2-manage-configuration-profiles-and-declarative-settings.md)). For Hydrant or custom EST, the test-issue endpoint does this without a device: it takes a certificate signing request, has the authority issue against it, and returns the result. Generate a throwaway CSR, post it to the authority by its numeric ID, and read the certificate back:

   ```bash
   export FLEET="https://fleet.example.com"     # your Fleet server
   export TOKEN="your-admin-api-token"          # the whole surface is Premium
   export CA_ID=1                               # the id of the authority to test

   openssl req -new -newkey rsa:2048 -nodes \
     -subj "/CN=fleet-ca-test" \
     -keyout /tmp/ca-test.key -out /tmp/ca-test.csr

   curl -sS --fail-with-body -X POST \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     --data "$(jq -Rs '{csr: ., return_pem_certificate: true}' < /tmp/ca-test.csr)" \
     "$FLEET/api/v1/fleet/certificate_authorities/$CA_ID/request_certificate"
   ```

   A certificate block in the response means the credential, the URL, and the protocol all work together; an error here is exactly what a clean create cannot surface. Omit `return_pem_certificate` and the certificate comes back wrapped as PKCS7 instead. The endpoint covers only Hydrant and custom EST; for custom SCEP, the profile install above is the end-to-end test.
3. **Record who owns the credential and when it expires.** An authority's token, password, or challenge has real reach and no human attached to notice when it lapses. Give it a named owner and a rotation date in the ownership register from [2.1](2.1-administration-model-and-deployment-choices.md).

The global administrator group owns these connections alongside the other integrations in Part II. Record a credential owner and rotation cycle for each authority, and finish each rotation by confirming a certificate can be issued with the updated value.

## Reference and troubleshooting

![Troubleshooting](../_assets/icons/troubleshooting-light.svg) Read the creation error to distinguish local validation from an outbound failure.

- **Local validation:** missing server private key, malformed or empty URL/name, invalid name characters, missing required fields, or more than one authority in a request.
- **Outbound call:** unreachable URL, firewall restrictions, or a protocol mismatch.

Either failure prevents the connection from being stored.

A connection that creates cleanly and then fails to issue is either the credential that creation did not test, for Hydrant, custom EST, and custom SCEP, or a delivery problem in the profile itself. Certificate delivery through profiles, including how profile status reads during issuance, is [5.2](../05-manage-devices/5.2-manage-configuration-profiles-and-declarative-settings.md). Apple MDM delivery diagnostics are [8.8](../08-troubleshooting/8.8-apple-mdm-diagnostics.md); Windows MDM diagnostics are [8.9](../08-troubleshooting/8.9-windows-mdm-diagnostics.md).

The endpoints and the publicly reachable proxy path are catalogued in [a.8](../09-appendices/a.8-api-action-and-endpoint-reference.md).
