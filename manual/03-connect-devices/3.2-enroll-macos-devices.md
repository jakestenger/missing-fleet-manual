# Enroll macOS devices

![Explanation](../_assets/icons/explanation.svg) A Mac arrives in Fleet over two separate channels that you turn on independently, and most of the confusion in this chapter comes from treating them as one step. **fleetd** brings queries, scripts, software and vitals. **MDM enrollment** brings profiles, commands, disk-encryption enforcement, lock and wipe. A Mac can have either without the other, and both states are normal for a while.

[3.1](3.1-enrollment-design-and-host-lifecycle.md) covers what enrollment establishes in general: the host record, the fleet assignment, and the credentials. This chapter covers the macOS-specific part: which path to choose, what each one requires, and how to tell a Mac that is part-way through from one that is stuck.

## The decision you are making

Two questions, and they are independent of each other.

**How does MDM get turned on?** Decided by how the Mac was bought and how it reaches you.

| Path | Use it when | What the console shows |
|---|---|---|
| **Automated Device Enrollment (ADE)** | The Mac is in Apple Business and company-owned. Enrollment happens during Setup Assistant, before anyone logs in | On (company-owned) |
| **Manual profile, company-owned** | The Mac is not in Apple Business, or it is already deployed | On (manual) |
| **Manual profile, personal (BYOD)** | The Mac belongs to the person using it | On (manual - personal) |

**How does fleetd get installed?** By a package you build and deliver. On the ADE path Fleet delivers it for you; on the other two you deliver it yourself.

Those strings are what the **console** displays. The database and the API spell the first one `On (automatic)`, and the host filter spells it `automatic`; [8.6](../08-troubleshooting/8.6-server-state.md#one-status-three-vocabularies) has the mapping, and it matters the first time you write a query from something you read on screen.

### What personal enrollment actually changes

This is a capability boundary rather than a label. Fleet builds a personal enrollment profile with a **reduced set of MDM access rights**: it takes the full set and removes device lock and device erase. A company-owned profile carries all thirteen rights, a personal profile carries eleven.

So on a personally-enrolled Mac, Fleet cannot lock the device and cannot wipe it, and that is enforced by the profile the device is holding rather than by a Fleet-side permission you could change afterwards. Changing your mind means re-enrolling with the other profile.

The mechanism explains the status string. Fleet appends a `byod` parameter to the MDM server URL inside the personal profile. The MDM stack surfaces URL parameters to the check-in handler, which reads it during `Authenticate` and records it on the host record, where it becomes `host_mdm.is_personal_enrollment`. That is also why the distinction survives on the host rather than living only in whatever you clicked.

### What each path needs first

| Path | Prerequisites |
|---|---|
| ADE | Apple Business connected with an ABM token uploaded, an APNs certificate, and the device assigned to Fleet as its MDM server in Apple Business. [2.7](../02-administer-and-deploy-fleet/2.7-apple-mdm-configuration.md) covers all three |
| Manual, either kind | An APNs certificate. No Apple Business involvement |
| fleetd, any path | A Fleet URL the Mac can reach over TLS, and an enroll secret for the fleet you want it in ([3.1](3.1-enrollment-design-and-host-lifecycle.md)) |

**Two of these surfaces are Fleet Premium.** Downloading the manual enrollment profile returns a licence error on Fleet Free, and so does downloading the default Setup Assistant profile. The over-the-air enrollment page carries no licence check at this release. What that leaves a Free deployment in practice is **not documented as a supported matrix anywhere**, and this manual does not assert one; if you are on Free and planning around manual enrollment, confirm it against your own instance before building a rollout on it.

## Installing fleetd

![How-to](../_assets/icons/howto.svg) You build a package, then deliver it.

```sh
fleetctl package --type=pkg \
  --fleet-url=https://fleet.example.com \
  --enroll-secret=<secret> \
  --fleet-desktop \
  --enable-scripts
```

The two optional flags are worth deciding rather than copying. `--fleet-desktop` includes Fleet Desktop, which is what gives the end user a menu bar item, the **My Device** page and self-service software; without it the other components still run and the person on the Mac has no Fleet-facing surface at all. `--enable-scripts` decides whether this host will run scripts, and a package built without it produces hosts you cannot run a script against later.

The enroll secret is baked into the package, landing at `secret.txt` in Orbit's root directory. That is one of the places an old secret hides when you rotate, which [3.1](3.1-enrollment-design-and-host-lifecycle.md) covers.

### Taking the secret from a configuration profile instead

`--use-system-configuration` builds a package carrying no secret and no Fleet URL, reading both from an Apple configuration profile at install time.

```sh
fleetctl package --type=pkg --use-system-configuration
```

Reach for it when you do not want the credential sitting inside an installer in a software repository. It only works on a Mac that is already MDM-enrolled, because the profile has to arrive first, and **the ordering is the whole trick**: MDM enrollment, then the profile carrying the URL and secret, then the package. Install the package first and it has nothing to enroll against.

On such a host `secret.txt` is **absent** rather than empty, and a `fleet_url.txt` appears instead. [8.2](../08-troubleshooting/8.2-log-surfaces.md#827-the-rest-of-the-orbit-root-directory) reads the rest of that directory.

### On the ADE path, Fleet installs it for you

A Mac enrolling through Automated Device Enrollment gets fleetd from an MDM command Fleet issues as part of its post-enrollment work. You deliver nothing by hand.

That convenience has one well-known failure, worth knowing before a rollout rather than after: the install command is issued once and nothing retries it, so a Mac can complete ADE enrollment perfectly and end up with **MDM on and no agent**. [8.1](../08-troubleshooting/8.1-diagnostic-method.md#the-half-enrolled-state) describes the shape, and [8.4](../08-troubleshooting/8.4-host-side-investigation.md#845-the-half-enrolled-state-mdm-without-an-agent) covers detection and recovery. Audit after a bulk enrollment rather than assuming both channels arrived together.

## The ADE sequence, in order

Worth reading once even if you never drive it by hand, because ADE support questions are almost always about which of these did not happen.

1. The Mac is assigned to Fleet as its MDM server in Apple Business. Fleet learns about it on its next sync.
2. Fleet assigns the device an enrollment profile, which is what makes Setup Assistant offer, or require, enrollment.
3. The device is unboxed or wiped and reaches Setup Assistant.
4. It enrolls, before any user account exists.
5. Fleet runs its post-enrollment work: the fleetd install, a bootstrap package if you have one, and the setup experience.

Steps 1 and 2 each leave a visible timestamp, and the gap between them is where ADE problems live. A device with an assignment time and no push time was never told to renew its enrollment, which [8.8](../08-troubleshooting/8.8-apple-mdm-diagnostics.md#886-assignment-time-but-no-push-time) covers.

**Setup Assistant behaviour is configured, not inherited.** Whether enrollment is mandatory, which panes are skipped, and whether the MDM profile can be removed are set by the profile Fleet sends Apple. [2.7](../02-administer-and-deploy-fleet/2.7-apple-mdm-configuration.md) owns that.

## Manual enrollment, in order

1. Turn on MDM and confirm the APNs certificate is valid ([2.7](../02-administer-and-deploy-fleet/2.7-apple-mdm-configuration.md)).
2. Get the enrollment profile, choosing company-owned or personal. That choice is not reversible without re-enrolling.
3. Deliver the profile. Someone installs and approves it on the Mac.
4. Deliver the fleetd package, separately.

Step 3 is the one with a person in it, and the thing to tell them is that macOS asks twice: once to download the profile, once to install it in System Settings. A profile downloaded and never installed is the most common "it did not work" on this path.

## Verifying an enrollment

![How-to](../_assets/icons/howto.svg) Check both channels, because either can be the one that failed.

**From Fleet.** The host appears and its MDM status matches the path you used. A status of `Pending` means Apple Business has told Fleet about a device that has not enrolled yet, which is the expected state between steps 1 and 3 above.

**From the Mac**, with a shell or a script:

```sh
# Is MDM on, and to whom?
sudo profiles status -type enrollment

# Did fleetd install and enroll?
sudo ls -la /opt/orbit
sudo launchctl print system/com.fleetdm.orbit
```

`profiles status` answers the MDM half in three lines: whether the device came through Automated Device Enrollment, whether MDM enrollment is on and user-approved, and which server owns it. The presence of `secret-orbit-node-key.txt` in Orbit's root answers the fleetd half. [8.4](../08-troubleshooting/8.4-host-side-investigation.md#844-macos-mdm-truth-from-the-host) reads both in detail.

**The two answers disagreeing is information, not a fault.** MDM on with no Orbit root is the half-enrolled state above. An Orbit root with no MDM is an ordinary agent-only host, which is a perfectly good state if queries were all you wanted.

## Who owns it afterwards

**The APNs certificate**, which expires annually and takes every Apple device's MDM channel with it when it does. It is renewed with the same Apple Account that created it, and losing that account means re-enrolling the estate. [2.7](../02-administer-and-deploy-fleet/2.7-apple-mdm-configuration.md) covers the renewal calendar.

**The gap between the two channels.** A count of Macs with MDM on and no recent osquery check-in is worth putting somewhere you look at regularly, rather than running it after someone complains.
